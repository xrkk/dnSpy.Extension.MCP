## 1. MCP 使用方式

### 1.1 连接与握手

本扩展把 dnSpy 变成一个 MCP（Model Context Protocol）服务器。AI 客户端通过 **MCP Streamable HTTP** 传输连接:

1. `POST <服务器基址>/mcp`, 方法名放在 JSON-RPC `method` 字段, 参数放 `params`;
2. 首次调用 `initialize`（带 `protocolVersion`、`capabilities`、`clientInfo`）完成握手, 服务器返回自己的能力声明并分配会话（后续请求带 `Mcp-Session-Id` 头）;
3. 发送 `notifications/initialized` 通知;
4. 之后即可调用 `tools/list`、`tools/call`、`resources/list`、`resources/read` 等标准方法。

服务器基址在 dnSpy 设置页（视图 → 选项 → MCP 服务器）配置:

| 模式 | 典型地址 | 说明 |
| --- | --- | --- |
| 默认本地 | `http://localhost:15378/mcp` | 只监听回环, 免 token |
| Host-Only 远程 | `http://192.168.204.240:15100/mcp` | 绑定虚拟机 host-only IP, 免 token 但仅信任直连宿主 CIDR（如 `192.168.204.1/32`） |
| Bearer Token 远程 | 同上 | 设置页启用 token 后所有端点 401, 凭 `Authorization: Bearer <token>` 访问; token 只在应用时显示一次 |

`GET <基址>/health` 返回 `{"status":"ok","service":"dnSpy MCP Server"}`, 可用作存活探测。

### 1.2 Python 客户端（推荐）

仓库自带标准库实现的客户端 `dnspy_mcp`（`pip install -e .` 后可用）:

```python
from dnspy_mcp import DnSpyClient

c = DnSpyClient("http://192.168.204.240:15100/mcp").connect()  # initialize + initialized
tools = c.list_tools()                    # 工具目录（等价 tools/list）
asm = c.call_tool_json("open_files", {"paths": [r"C:\samples\TestIL.dll"]})
hits = c.call_tool_json("search_types", {"query": "License", "assembly_name": "TestIL"})
res = c.list_resources()                  # 资源清单（等价 resources/list）
doc = c.read_resource("dnspy://docs/tool-workflows")
c.close()                                 # 关闭会话
```

命令行形态: `dnspy-mcp-http --url <基址> --body-utf8 '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'`（调试用）; `dnspy-mcp-stdio` 提供 stdio 桥接。

### 1.3 典型工作流（AI 视角）

```
open_files(载入样本) → search_types / search_members(定位目标)
  → get_type_info / list_methods(看结构) → decompile_method / decompile_by_token(读代码)
  → find_callers / find_callees / find_references(影响面)
  → [静态改写] get_method_il → patch_method_il / nop_method / force_return → revert_method_il / save_assembly
  → [结构化编辑] edit_begin → edit_compile+edit_import / edit_apply → edit_review → edit_commit / edit_rollback
  → [动态调试] debug_launch → debug_set_breakpoint → debug_wait_event → debug_get_stack/get_locals → debug_terminate
```

按任务组织的完整序列见资源 `dnspy://docs/tool-workflows`。

## 4. 行为要点（AI 使用须知）

1. **通告面即能力面**: 生产配置 `tools/list` = 72; 看不到的工具（如 `edit_test_clock`）直呼会得到域错误包（`CAPABILITY_UNAVAILABLE`/`EDIT_CAPABILITY_UNAVAILABLE`）而非 Unknown tool——不要因能直呼就认为它可用。
2. **请求幂等**: 可变操作按 `request_id` 去重——重复同 ID 会回放缓存响应, 同 ID 不同载荷报 `REQUEST_ID_REUSE`。每次执行的 `request_id` 必须唯一（建议带 uuid 后缀）。
3. **调试生命周期**: `debug_launch` 后入口暂停是瞬态的（事件读取会消费它）; `debug_pause` 仅在 running 态合法; 断点需要 `mvid` + `module_sha256`（`debug_list_modules` 获取, 模块清单为异步填充需短暂轮询）; 会话结束务必 `debug_terminate`（写类编辑工具要求调试 idle）。
4. **编辑产物安全**: `save_assembly` 只写 ArtifactRoot, 永不覆盖原样本; 编辑事务归属 MCP 会话, 会话关闭时未决事务自动中止。
5. **限制**: 请求体上限 1 MiB、工具结果 8 MiB、并发长连接 8、每实例会话 16——逐个调用、每步关会话是最稳的用法。
6. **覆盖基线**: 本目录数据与 2026-09-29 情景链路测试层验收基线一致（net48 实测 72; `edit_compile` 由独立提供者通告, 计入编辑族 18）。
