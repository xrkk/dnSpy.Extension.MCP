# 0004: 情景由声明式脚本统一重放执行，AI 是设计者不是执行者

（注: 2026-09-29 阶段 2 复核将本文的"声明式脚本 + 专用 runner"机制简化为 pytest 用例 + 录制代理，见 ADR-0009; 重放执行、统一账本、AI 角色三点结论不变。）

每个情景交付"情景规格（步骤、断言、复位）+ 声明式脚本（YAML/JSON：调用序列、响应到下一步请求的变量绑定、期望断言）"，由基于 `dnspy_mcp` Python 客户端的统一 runner 批量执行，产出结构化执行账本（每步请求/响应/断言判定）与自动覆盖矩阵。理由：可复现使失败可原样重放归因；token 成本一次性；账本格式统一，100 个情景的证据是一个结构化文件集而非 100 份散文。拒绝 AI 即兴逐个跑（不可复现、断言退化为主观判断、成本巨大）；AI 使用体验抽样可作为后续附加，不在本层承诺。
