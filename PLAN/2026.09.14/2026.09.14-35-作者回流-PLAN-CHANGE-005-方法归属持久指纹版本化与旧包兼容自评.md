## PLAN-CHANGE-005 — 检查点包 v2：方法归属绑定的持久强指纹与 v1 旧包只读兼容

- **被偏离的冻结规范**：P03 v5「包格式」段（`manifest.json` 的 `format` 固定 `dnspy.edit.checkpoints.v1`）与 §8 三态/迁移语义（image 不同即可在语义相等时判 `validated_drift` 并建立 migration child）；P02 v11 对持久语义指纹角色的冻结。
- **上游依据**：CHK-022 的 D2 反例——历史 `ComputeRoundtrip` 对「交换两个同签名方法体」完全不可见，而 `Compute` 的可见性依赖通道发射顺序，因此旧持久语义不能作为方法级归属的判据；REQ-011/REQ-022、CON-023、RACC-013、总纲 ACC-013、OUT-002/OUT-003。
- **变更内容**：
  - 新谱系（含显式 `edit_accept_live` 建立的新谱系）写 `dnspy.edit.checkpoints.v2`；v1 不变更既有 manifest 结构与值，未知 `format` 继续 `EDIT_OPERATION_VERSION_UNSUPPORTED`，不静默升级 v1。
  - v2 的 result semantic fingerprint 采用**方法/类型归属绑定**的强投影：`mgp/param/body/local/il/sp/eh` 绑定到方法 owner（sequence point 另绑定指令位置），`tgp/interface` 绑定到类型 owner；owner 含声明类型、名称、完整签名与泛型元数，按结构化编码（数组/长度前缀，非未转义分隔符拼接）；`MethodKey` 不足以消歧时使用强入口专用稳定结构化 key；无法消除的 owner 歧义以 `EDIT_CAPABILITY_UNAVAILABLE` 显式失败，不产生看似成功的哈希。
  - 保留冻结定义：历史 `Compute`/`ComputeRoundtrip`、`dnspy.edit.op.v1` 信封、`source_identity.v1` 基线语义（v2 节点基线仍按历史算法计算并与强摘要分开记录）、T002 瞬态 `ComputeExternalGuard`（仍只用于实时漂移比较）。
  - v1 包只读兼容：按历史算法 exact 验证、导航、导出，并可在 exact head 下追加/分支（继续写 v1、不重算旧节点、不升级既有包）；v1 的 image 不同无论历史语义是否相等一律 `unverified_drift`，无确认与 migration 通道，恢复路径为用户已有的显式 `edit_accept_live`（保留旧谱系，建立 v2 新谱系），不新增迁移 API。
  - 分类按 lineage 的 `format` 选择算法且禁止跨版本混比：v2 才允许「image 不同 + 强语义相等 + 结构/往返通过」的 `validated_drift`，经显式确认建立 migration child；migration 前置校验（v1 → `EDIT_REPLAY_UNVERIFIED`，非 validated → `EDIT_REPLAY_CONFIRMATION_REQUIRED`）。
- **采纳理由**：方案 B 让格式本身固定算法，避免新增 `semantic_algorithm` 字段与操作版本变更，一次新谱系迁移即闭环；旧算法对方法换体不可判定，因此不能为 v1 保留 image-漂移→migration 通道。
- **历史兼容**：v1 包及其节点/操作/payload 字节保留；旧产品读取新包硬拒绝（证据见下）；v2 新谱系首提交起即写入强摘要，不回溯重算历史。

- **机器套件范围**：不改变既有套件基数；新增版本向量固定包与正式 runner（见证据索引），P03StoreHarness 更新未知 format 探针（v2 已知、v3 未知）与旧包 format 断言。
