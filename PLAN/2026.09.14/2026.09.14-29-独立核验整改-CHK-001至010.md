## 1. 代码整改明细（对照 CHK 证据）

### CHK-001 / REQ-016 本地取消

- `CancelOrphanedTransactionFromUi` → `CancelTransactionFromUi`：返回 `canceled|busy|no_transaction`；活动事务在 `OperationBusy==false && CommitStarted==false` 时可取消，属主在线不再是前置条件；孤儿事务仍无条件可取消。
- 快照新增 `OperationBusy/CommitStarted/CanCancel`；按钮门控改为 `CanCancel`；按钮文案 "Cancel current transaction (rollback)"；UIAutomation ID 不变（McpEditCancelButton 等）。
- 实施方决定：P09 v1 IMP-001 的 OwnerClosed 收窄被判定为对上游 REQ-016 的过度收窄，整改方向为恢复需求原义而非登记需求变更。该决定按 PLAN-CHANGE 流程留作者追认位：若作者裁决保留收窄，需改需求并重走审核。

### CHK-002 / REQ-016 检查点浏览

- idle（active==null）不再短路返回；`history.LoadAll()` 全量加载。
- 快照新增 `ExplorerCheckpointRow`（LineageId/CheckpointId/ParentCheckpointId/Kind/ImageShaPrefix/SemanticPrefix）；UI 每谱系生成逐检查点子节点（"checkpoint <id> parent <p|root> kind <k> image <12> semantic <12>"）。

### CHK-003 / CON-004 全量漂移守卫（版本安全）

- 冻结不变：`EditFingerprint.Compute/ComputeRoundtrip`（语义指纹）、全部持久检查点值（ResultImageSha256/ResultSemanticFingerprint）、`history.Assess` 输入语义、工具可见指纹。
- 新增：`ComputeExternalGuard` = 冻结语义通道 + 入口点行 + AssemblyRef 行 + Win32 资源树哈希 + 模块/类型/方法/字段 CDI 行。`EditWorkspace.BaselineExternalGuard`（构造时捕获）与 `CurrentExternalGuard()` 同函数成对比较。
- 接入点：edit_review 入口、edit_commit 入口、ApplyTransactionToLive 恢复校验、emergency 清理校验、测试导航入口；均为"live 漂移检测"，不写入任何持久值。
- 新证据钩子：`edit_test_external_mutation` 新 case `live-conflict:mutate-entrypoint`（仅换入口点；语义指纹不变、守卫必变）。
- 实施方决定：不扩语义投影（保持历史兼容），以并行守卫闭合 CON-004 可观测性缺口；是否把守卫行并入语义指纹由作者裁决（并入即全部旧历史三态迁移，属 PLAN-CHANGE）。

### CHK-004 / REQ-005 身份断言

- `AssertIdentityRowsUnchanged`/`AssertNativeRowsUnchanged` 比较对象由"已编辑私有副本 vs 未编辑 live"改为"live vs 事务基线字节（BaselineBytes）"。合法入口点/引用变更（私有侧）不再误报 EDIT_LIVE_MODULE_CONFLICT。

### CHK-005 / REQ-006 资源编解码

- `ReadNameString`：byteCount==0 合法（空名称）。
- `EncodeEntry(name, kind, value, preservedTypeCode)`：重载保留 Stream 与 ByteArray 的类型码区分；`managed_resource_update` 传入 `target.TypeCode`。
- 未编辑条目（含空名称、自定义类型载荷）按原始字节/类型保留。

### CHK-007 / REQ-013 风险回显

- Commit 响应 `confirmed_risks` 由 ID 列表改为完整风险事实数组（risk_id/kind/object/description/confirmation_required…）；`cross_assembly_inbound` 行附加 `affected_references`（module/assembly_ref_token/matched_name/sites/risk_id）。
- `ImpactScan` 填充 `LastInboundReferences[riskId]`（进程级，仅供提交回显绑定）。

### CHK-008 / CON-005 预生成完整逆计划

- Commit 在 `PrepareCommit`（已验证检查点包）之后、首个 live 写入之前物化 `inversePlan`（每操作的持久编译逆 JSON，绑定 PostHeadCheckpointId）。
- `ApplyTransactionToLive`：`live_apply` 故障档在"操作已改 live、Outcome 未入列"处注入；恢复路径对失败操作应用其预生成编译逆（EDIT_HISTORY_CONFLICT = 该操作未发生 live 写入，跳过是正确恢复），再执行前缀 Outcome 逆；基线守卫（语义+全量）双校验。
- 设计内行为确认：post-prepare 提交失败经完整恢复后由 `CleanupPreparedOrEnterRecovery(Transaction,…)` 结束事务并清理 owned temp（EndLocked→idle）；恢复不完整才进入 `live_state_unknown`。该行为即 ACC-009 "要么完整恢复要么 UNKNOWN" 的实现。
- 提交响应新增 `live_recovery` 绑定证据：`{inverse_plan: "pregenerated_compiled_state", inverse_plan_operations, inverse_plan_bound_checkpoint_id, inverse_plan_complete_before_live_write: true}`。
- 测试钩子契约扩展：`edit_test_storage_fault` stage 枚举 + `live_apply`；`edit_test_external_mutation` case_id 枚举 + `live-conflict:mutate-entrypoint`（p03-tool-schemas.json 同步，validate_p03_contract PASS）。

### CHK-009 / RACC-001/003/009 生成链唯一权威

- `contract_source.py`：OPERATIONS 扩至 37（P04/P07/P08 行移植入源，含新增 8 个 `_remove` 种类的诚实 delete_policy）；`MACHINE_SUITE_OPERATION_COUNT=22`、`SCHEMA_OPERATIONS` 冻结 P02 机器套件（工具模式 oneOf、故障矩阵、RACC-003 案例表均取前 22）。

### 全回归新发现并修复：屏障暂停期超时语义（P03 起回归，非本轮整改引入）

CHK-006 全回归复跑 P02 机器套件时 `run_barrier_concurrency.review_vs_timeout` 确定性失败：事务停在 `review_before_validation` 屏障时推进测试时钟 600000ms，`edit_test_clock` 响应 state 不为 idle。归因：P03 提交 `2142266` 在 `ExpireLocked` 加了 `!active.OperationBusy`（保护进行中的实时变更不被超时杀死），同时意外废除了 P02 冻结契约"屏障暂停的事务在空闲边界超时"（EndLocked 本就会释放屏障并让暂停调用收到 NOT_FOUND；忙标志只用于推迟工作区释放）。修复：`parkedAtBarrier = testBarrier != null && testBarrier.Entered` 时保持可超时，进行中变更仍不可超时。该缺陷自核验固定 HEAD `8e725db` 即存在（P02 套件在核验会话未复跑，未进入 CHK 清单）；属 CHK-006"完成当前组合的规定回归"的直接产物。
