## 1. 范围与非目标

**核心维护范围**：
1. 新操作种类（`dnspy.edit.op.v1` 新增 7 种，总 30→37）：`managed_resource_add` / `managed_resource_update` / `managed_resource_remove`（标准 `.resources` 条目级：标量/字符串/字节数组；非标准或自定义序列化条目只允许**整体字节替换**与元数据查看——载荷哈希/类型名/长度，绝不反序列化）、`win32_resource_add` / `win32_resource_remove`（RT_GROUP_ICON/RT_ICON 等原生表行的增删与重组——图标组 ID 关系在删除 RT_ICON 时校验引用并拒绝断链）。全部复用 edit_apply 事务/审查/提交/检查点/逆链。
2. 资源导入导出：`edit_resource_import`（VM 文件路径→事务内资源行；返回 file_id/长度/SHA-256）与 `edit_resource_export`（资源行→ArtifactRoot 下 VM 文件路径；同身份证据）——复用 P03 checkpoint store 的文件身份机制；**不提高任何内联上限**（超限内联仍按现有传输规则拒绝——RACC-008）。
3. 最小强名称兼容（REQ-014/RACC-016）：默认一切编辑保留强名称身份；仅在**动态验证明确因强名称失败**后，允许通过 `edit_apply` 既有操作（新种类 `strong_name_remove`——清 PublicKey + 清/降级签名标志）建立"去强名称调试分支"；建立时若已加载模块存在对被编辑程序集的强名称引用，报告影响（复用 P07 `edit_impact_scan` 的 loaded_modules 范围）；严格不可恢复样本返回能力限制（诚实边界）。

**直接依赖范围**（只读复用）：P02 操作注册表骨架、P03 提交/检查点/文件身份（EditCheckpointStore 的 file_id 机制）、P06 部署链、P07 edit_impact_scan 范围语义。

**明确排除范围**：反序列化/实例化任何自定义序列化资源对象（CON-019/REQ-021 硬边界）；UI/文档/最终验收（P09）；重构 P02/P03 任何既有机制。

## 2. 现状盘点（2026-09-14 实测）

- 操作语言现状：30 种（P02 22 + P04 4 + P07 4）；无任何资源种类。
- 资源面：dnlib `ModuleDef.Resources`（`EmbeddedResource`（字节）/`LinkedResource`（文件）/`AssemblyLinkedResource`）；Win32 资源在 `NativeResource` 列表（`dnlib.DotNet.Writer` 下的 `Win32Resource` 行，含 RT_GROUP_ICON/RT_ICON/RT_VERSION 等，dnSpy 可编辑）；`System.Resources.ResourceReader` 只用于**读取标准条目枚举**——不用于反序列化自定义对象。
- 指纹/重放：`EditFingerprint` 投影含 `resource|类型|名称|SHA(字节)` 行——**仅覆盖 EmbeddedResource**；托管资源操作天然改变指纹；**Win32 原生行不在投影内**（AUD-001 更正）——其一致性沿用 P07 三层先例：检查点图像 SHA（字节级）+ `edit_review` 在 Win32 类操作暂存时的私有/live 原生资源行断言（行集逐行 type/name/langId/字节 SHA）+ harness 图像级断言；投影零变更（既有谱系零退化）。重放确定性＝载荷驱动（见 IMP-001/003 内嵌字节语义）。
- 文件身份：P03 `EditCheckpointStore` 已有 ArtifactRoot 下文件写入与 file_id/长度/SHA256 身份机制（checkpoint/export 同型）。
- 强名称面：`AssemblyDef.PublicKey`（含清空）、`AssemblyDef.PublicKeyToken` 派生、模块 `Assembly.signature`（dnlib 写出时由 PublicKey 重新计算/清空）；强名称引用=其他已加载模块 AssemblyRef 带 PublicKeyToken/PublicKey。
- 容量：`EditWire.MaxResourceBytes=8 MiB`＝活模块内嵌资源总量门与单载荷上限（apply 路径在每次资源操作后重检）；传输 1 MiB 请求限制（ACC-008 的"超限内联拒绝"界）；大载荷走 VM 文件路径——服务端读字节后内嵌入操作（不进请求正文）。
- P01/P03 的副作用哨兵先例：恶意 fixture（含激活器资源）+ 进程/文件哨兵断言"无实例化"。

## 3. 实施项（IMP）

### IMP-001 托管资源操作（3 新种类 + 标准条目域）

- 范围：`managed_resource_add` `{kind, name, resource_type?"embedded", data_base64 | file_id}`（整资源字节级新增；embedded 默认）、`managed_resource_remove` `{kind, target:{name|index}, remove_mode:"reject_if_referenced"}`、`managed_resource_update` 双模式：`{kind, target, entry:{name, value_kind, value}}`（标准条目级——string/bool/数值标量/字节数组，重建标准 .resources 字节流）或 `{kind, target, data_base64|file_id}`（整体字节替换——非标准/自定义对象的唯一编辑面）。
- 目标行为：
  - 标准 `.resources` 条目编辑（值域冻结，AUD-006）：string、bool、byte/sbyte/short/ushort/int/uint/long/ulong/float/double（9 数值）、byte-array（含 stream 码——按字节数组读写）；Char/DateTime/TimeSpan/Decimal/自定义序列化＝编辑域外（元数据查看+整体替换，CON-019）；枚举只经 `ResourceReader` 读标量域，绝不反序列化；
  - 自定义对象：查看面（`edit_status`/diff 只给 类型名+长度+SHA-256）；任何隐式反序列化＝失败（ACC-007 哨兵）；
  - 逆：add↔remove（捕获字节）；update 捕获旧字节整体回写；风险 `resource_change`（公开资源名＝confirmation_required）；
  - **载荷语义**：操作载荷始终内嵌字节（`data_base64`）——不依赖任何文件存在性；检查点包按既有信封存操作行（字节在载荷内），包级按 SHA-256 去重（总纲 §5.2 行 175 冻结语义）；信封载荷白名单新增资源/强名称种类行（既有仅 method 两种类）。
  - **标准条目重建确定性**：`EditResourceCodec` 自实现确定性 `.resources` 写出器——固定 magic/版本头、文档化稳定名字哈希函数、按 (hash, ordinal 名) 排序、ResourceTypeCode 固定编码；跨进程/跨面（私有/live/重放）字节级一致（harness 断言跨进程写出哈希相等）。
- 实际落点：`EditOperationRegistry.cs`（3 case+逆）、`EditResourceCodec.cs`（新——标准条目枚举/重建，绝不反序列化）、契约四处同步（30→33）。
- 允许裁决的纯实现细节：条目重建的规范化细节（对齐/版本头——以重载读回一致为准）。

### IMP-002 Win32 资源与图标组（3 新种类）

- 范围：`win32_resource_add` / `win32_resource_update` / `win32_resource_remove` `{kind, target?, type, name_id|name_string, lang_id?, data_base64}`（Win32Resource 行字节级；update＝整行字节替换并复用图标组校验）。
- 目标行为：RT_ICON 删除时校验同组 RT_GROUP_ICON 引用（图标目录项指向的图标 ID）——断链＝拒绝（"图标关系有效"失败条件）；RT_GROUP_ICON 增删同步维护目录数据（载荷即数据，不做隐式修补）；逆＝字节捕获回写；纯 IL 模块上 NativeResources 为空表——新增首个 Win32 资源行即建立原生段（dnlib writer 支持）。
- 实际落点：`EditOperationRegistry.cs`（3 case+逆）+ `EditResourceCodec.cs`（RT_GROUP_ICON 目录解析校验）；契约同步；review 原生行断言（AUD-001 (ii)）。
- 允许裁决的纯实现细节：目录解析容错边界（畸形目录＝拒绝而非猜测）。

### IMP-003 资源导入导出（VM 文件路径）

- 范围：`edit_resource_import` `{request_id, transaction_id, expected_revision, vm_path, resource_name, resource_type?}` 与 `edit_resource_export` `{request_id, transaction_id?, lineage_id+checkpoint_id, resource target/identity, output_path?}`。
- 目标行为：import＝服务端按 VM 路径读取字节（返回 file_id/长度/SHA-256），暂存为对应种类的**内嵌字节操作**（`resource_type`∈{embedded,linked,win32} 分派至 managed/win32 种类；字节不进 MCP 请求正文）；export＝把已提交资源行写出至 ArtifactRoot 下路径，返回 file_id/路径/长度/SHA-256；默认工作输出原子替换、原始样本不覆盖（CON-016 消费）；**任何内联上限不变**（超限内联仍拒绝）。
- 实际落点：`EditTransactionCoordinator`（两工具入口）+ checkpoint store 文件身份复用 + schema。
- 允许裁决的纯实现细节：路径校验消息、原子替换实现（临时文件+move）。
