## 1. 范围与非目标

**核心维护范围**：新增 MCP 工具 `edit_compile`（名称在本方案冻结）：以 dnSpy 公开 `ILanguageCompilerProvider`（MEF `[ImportMany]`，实测解析为 `dnSpy.Roslyn.Compiler.CSharp.CSharpLanguageCompilerProvider`，S02 轮证）编译 AI 提交的 C# 源码，返回**编译诊断 + 程序集内存载荷 + Portable PDB 内存载荷的产物身份**（载荷不落盘、不导入任何模块——只登记产物供 P06 受控消费）。复用 P01 的权威调用上下文与 VM 门禁；编译在 dnSpy UI 进程内执行（provider 为 dnSpy MEF 部件，只能在进程内取得）。

**直接依赖范围**（只读复用）：P01 `McpCallContext`/传输层；`McpToolProvider` 注册机制；编译前端不修改 P02/P03 事务内核（工具注册与传输层落点复用 P01 机制）；`CompilerProjectInfo`/`CompilerDocumentInfo`/`CompilationResult`/`CompilerDiagnostic`（dnSpy 公开 Roslyn 契约，S02 与可行性 spike 用例证实）。引用钉住使用公开契约 `IAssemblyReferenceResolver`；S02/spike 中的 `PinnedReferenceSet` 是 spike 自有 unsafe 辅助类（`tests/spikes/dnspy-feasibility/FeasibilityExtension.cs`），**生产移植为 IMP-001 义务**（或以等价公开契约实现替代）。

**明确排除范围**：结果导入（P06：稳定签名匹配、内嵌 PDB 转换、CDI/作用域/局部/异步）；程序集/模块身份编辑（P07/P08）；`method_body_replace` 或任何事务操作的改变（编译产物不进入 `edit_apply`，总纲 §12"不发布缺少检查点的产品提交路径"的编译侧对称约束：**编译前端不产生任何模块变更**）；analyzer/source generator/Roslyn scripting/build task 的任何启用路径（CON-022 硬边界）。

## 2. 现状盘点（2026-09-14 实测）

- 公开契约存在且已验证：S02/S02-R1 两轮（x64/x86）证明 `ILanguageCompilerProvider.Create(CompilationKind.EditClass)` → `InitializeProject`（引用集）→ `AddDocuments` → `CompileAsync` 返回 `CompilationResult{Success, Diagnostics[], RawFile, DebugFile(RawFile=Portable PDB 内存载荷)}`；spike 与 `tests/spikes/dnspy-feasibility/FeasibilityExtension.cs` 均有可复用调用序列。
- 无生产工具暴露该能力：32 个静态工具中无编译入口（baseline snapshot 实测）。
- S02 边界事实（"实验中发现并固定的接口边界"1-5 条逐条继承）：Portable PDB 内存载荷非内嵌格式（P06 转换）、sequence point 随体克隆、源 `PdbDocument` 不可手工插入、`PdbFileKind` 目标侧设置、编译/导入两边界分离。
- 安全事实：dnSpy 公开 Roslyn 编译不含 analyzer/generator 装载路径（`CompilerProjectInfo` 无扩展点参数——S02 契约面）；VM 门禁与 DNMCP_TEST 语义已在 P01 就位。

## 3. 实施项（IMP）

### IMP-001 编译会话服务（进程内）

- 范围：`Editing/EditCompileFrontend.cs` 新增——MEF 导入 `IEnumerable<ILanguageCompilerProvider>`，选择 `CanCompile(EditMethod|EditClass)` 的提供器（优先公开契约 `Language` Guid 精确匹配 C#，类型名启发式仅作后备；零或多个匹配＝`EDIT_CAPABILITY_UNAVAILABLE`）。
- 目标行为：`Compile(CompileRequest)` → 编译产物登记：`compile_id`、诊断数组（severity/code/message/location 映射 dnSpy 公开 `CompilerDiagnostic` 字段）、`assembly_sha256/length`、`pdb_sha256/length`（Portable PDB 内存载荷）、`target_platform`、产物常驻进程内有界缓存（对齐既有 begin 缓存的有界无淘汰模式，默认 8 项，超限拒绝——纯实现细节）。
- 引用集构造：以**目标模块**（已加载模块的 `Assembly` 引用闭包）为默认引用集——从 `module.GetAssemblyRefs()` 解析到已加载文档或磁盘路径；引用钉住经公开契约 `IAssemblyReferenceResolver` 实现：S02 复用的 `PinnedReferenceSet` 是 spike 自有 unsafe 辅助类，生产实现必须移植该辅助类或提供等价的公开契约实现（句柄钉住语义不变），unsafe 边界限于该辅助类内部。目标模块缺失时要求显式引用清单。
- 顺序：无前置。
- 实际落点：`Editing/EditCompileFrontend.cs`、`Editing/EditToolProvider.cs`（注册）、schema 契约。
- 允许裁决的纯实现细节：缓存大小、诊断字段裁剪。

### IMP-002 工具契约与安全限制（edit_compile）

- 范围：`edit_compile` 输入＝`{request_id, assembly_name|module_mvid, documents:[{path, content}], compilation_kind: "edit_method"|"edit_class", target_platform?, references_override?}`；输出＝`compile` 信封（compile_id、诊断、产物身份、`consumable_by_import: true`）。
- 安全限制（CON-022 落地）：输入契约**无** analyzer/generator/script/build-task 字段；`references_override` 只允许绝对磁盘路径白名单（既有 allowedSampleRoot 策略裁剪——路径策略属 P01 工具策略，超范围时 `EDIT_CAPABILITY_UNAVAILABLE`）。门禁范围澄清（AUD-004）：CON-022 的 VM 门禁子句只附加于**动态运行**；`edit_compile` 是进程内静态编译动作（无进程外执行），因此不挂 VM 执行门；REQ-023 的动态门禁语义在 P05 仅以"无动态运行路径"的事实满足——编译前端不存在任何执行编译产物的入口，该事实列入产出验收的禁止项断言。
- 不变量：编译产物不可被除 P06 导入器之外的任何工具消费（编译 ID 只进 P06 的导入契约——本方案仅登记）；不落盘（内存载荷 + 进程内缓存）。
- 实际落点：`Editing/Contracts/`（新工具 schema 或扩展现有冻结文件的模式）、`EditJsonSchemaValidator` 校验。
- 允许裁决的纯实现细节：schema 文件归属（新文件 vs 扩展 p03-tool-schemas.json——冻结时定一）。

### IMP-003 测试与验收资产

- 范围：harness 探针 `--compile-frontend-matrix`（有效源码：字段/方法/EH/泛型/using 诊断零错误+产物身份非空+Portable PDB 载荷可被 `ModuleDefMD.Load(PdbFileOrData=)` 载入；无效源码：语法错误/未定义类型/重复成员→诊断非空且 `Success=false`、无产物；禁止项：构造无 analyzer 字段的请求即契约层拒绝+源码内 `#if` 等预处理不启用扩展点——实证 Roslyn `CompilerProjectInfo` 契约面无装载路径）；集成驱动 `p03_vm_acc005.py`（真实 MCP 形状：有效编译+诊断核对+产物身份+二次编译 LRU+无效拒绝+capability 场景）；案例文件 `EDIT-ACC-005.json`（冻结命名；P05 填充编译动作子集，P06 后续扩展同一文件加入导入/保存/重载/断点动作完成 ACC-005 终判；证据身份以 run-id 区分——P05 取证 run-id 固定前缀 `p05-compile-`）。

## 5. 审核重点

1. 范围纪律：只编译不导入（S02 边界 5 与总纲 §12 分离规则）；产物只登记不消费。

3. 安全限制闭合（CON-022）：契约面无扩展点字段；引用覆盖走白名单；VM 门禁继承。
4. 产物身份与 P06 交接面：compile_id/双载荷身份/常驻缓存的淘汰语义可被 P06 稳定消费。
5. 双 TFM 构建义务（net48/net10.0-windows 0 警告 0 错误）。
6. 无后序依赖（P06 未编写不影响 P05 独立实施验收——产物消费者缺席时以登记语义验收）。
