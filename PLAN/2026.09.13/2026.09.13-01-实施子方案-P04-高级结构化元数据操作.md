**明确排除范围**：C# 编译导入（P05/P06）；资源/程序集身份/入口点操作（P07/P08）；调试行为（P01 既有）；UI/文档/客户端适配汇总（P09）；不改变既有 22 类操作的既有字段语义（只增不改；`method_update.impl_attributes` 的 MethodImpl flags 已存在，本方案不重复实现，仅在其文档中标注归属）。

## 3. 实施项（IMP）

> 所有新载荷字段经既有 `edit_apply` 归一化进入 `NormalizedOperations`，并在 `edit_review`（结构+往返+动态）与 `edit_commit`（compiled_state 逆、墓碑、检查点图像）中原样生效；新操作类型的 kind 进入 `EditWire.OperationKinds` 与操作 schema 冻结清单。dnlib API 为唯一事实来源：`IHasCustomAttribute.CustomAttributes`、`GenericParam.GenericParamConstraints`、`MethodDef.Overrides`、`TypeDef.ClassLayout(PackSize/ClassSize)`+`TypeAttributes.ExplicitLayout/SequentialLayout`、`FieldDef.MarshalType(NativeType)`、`ParamDef.MarshalType`、`MethodDef.ImplMap(ModuleName/Name/IsCharSet*)`+`MethodAttributes.PInvokeImpl`、`DeclSecurity(Action, Blob, Parent∈{Assembly,TypeDef,MethodDef})`、`FieldDef.InitialValue/RVA`。

### IMP-001 Custom Attribute 操作（attribute_add / attribute_remove）

- 范围：对 type/method/field/property/event/param/generic_param 七类定义及程序集（module 级 `Assembly.CustomAttributes`）附加与移除 Custom Attribute；assembly 目标以 `target:{scope:"assembly"}` 表达（与 IMP-007 的 security assembly 父级一致）。程序集身份编辑仍属 P08。
- 现状：删除守卫已统计 `CustomAttributes`；无编辑入口。
- 目标行为：`attribute_add`＝`{kind:"attribute_add", target:{token}, constructor:{结构化类型引用}, fixed_arguments:[常量数组], named_arguments:[{kind:field|property|type, name?, target_type, value}…], allow_multiple?}`；`attribute_remove`＝`{kind, target, match:{constructor, digest?, index=0}}`（同构造器多实例时以 `index` 序号精确选择，越界拒绝）。构造器引用必须解析到当前模块内唯一 MethodDef（.ctor，参数形状匹配 fixed_arguments）；`named_arguments` 值经既有常量编解码（`ParseConstant` 同源）。attribute 目标类型允许 type token 或 TypeRef/TypeSpec 结构化引用（`attribute_named_type` 值）。
- 前置：目标存在；构造器可达；参数形状合法。
- 依赖：无新外部依赖；复用结构化签名引用。
- 顺序：在 IMP-009（契约冻结）之前实现、随其一并冻结。
- 实际落点：`EditOperationRegistry.cs` 新增 kind 分支 + `EditOperationRegistry.Inverse.cs` 逆（attach 逆＝按 digest 移除、remove 逆＝按捕获的完整载荷重挂）；`EditDeletedRowsTombstone` 删除逆必须捕获被删定义的全部 attribute 行（子树表示扩展）。
- 位域所有权裁决：`TypeAttributes` 布局位 0x18 由 `layout.kind` 独占、`MethodAttributes.PInvokeImpl` 0x2000 由 `pinvoke` 独占——`attributes` 载荷携带这些位且对应结构化字段同时出现（或该位非默认而结构化字段缺省改变它）时结构性拒绝，杜绝双写歧义。
- 允许裁决的纯实现细节：digest 算法（规范化 JSON 的 SHA-256 前缀）、多实例匹配序号语义、`allow_multiple` 缺省＝false（目标类型非 AllowMultiple 时多挂拒绝，为 true 时按序号寻址）。

### IMP-002 泛型约束列表（generic_parameter_add/update.constraints）

- 范围：泛型参数的类型约束列表编辑。
- 目标行为：`constraints: [{type: 结构化类型引用, kind?: variance 之外无需}]`，整体替换语义（与 `attributes` 位 flag 的既有 special/variance 位并存：`GenericParamAttributes` 位不变仍由 `attributes` 承载）。约束目标必须解析为当前模块内类型或 corlib 类型；自约束/循环约束拒绝（既有删除守卫的 `ConstraintsUseGeneric` 同源判定用于校验）。`generic_parameter_add` 携带初始约束集。
- 实际落点：registry 两 kind 扩展 + 逆捕获旧约束集；墓碑/`generic_parameter_remove` 逆已捕获约束（现状代码已读 `GenericParamConstraints`，补全恢复侧）。
- 纯实现细节：约束去重序（按结构化引用规范化序）。

### IMP-003 Override 映射（method_add/update.overrides）

- 范围：MethodOverrides 行（方法声明×基虚方法）。
- 目标行为：`overrides: [{method: 结构化方法引用(名称+声明类型+签名), declaration: 结构化方法引用}]` 整体替换语义。双方必须为 virtual（`MethodAttributes.Virtual`）；声明方法不能是当前方法自身；映射不能重复。`method_add` 可携带初始映射。
- 实际落点：registry 扩展 + 逆捕获旧映射集；重载验证（IMP-010 的重载样本断言 `MethodDef.Overrides` 语义）。
- 纯实现细节：方法引用解析歧义时以声明类型+签名形状唯一化。

### IMP-004 类型布局与字段偏移（type_update.layout、field_update.field_offset）

- 范围：`ClassLayout`（PackSize/ClassSize）与 `TypeAttributes.ExplicitLayout|SequentialLayout` 组合，及显式布局下的 `FieldDef.FieldOffset`。
- 目标行为：`layout: {kind: "auto"|"sequential"|"explicit", pack: uint16(0 表示省略), size: uint32(0 表示省略)}`；`kind:auto` 清除布局行与两位布局 flag；sequential/explicit 设置对应 flag 并写入/移除 ClassLayout 行。`field_offset: uint32|null` 仅在 owner 为 explicit 布局时接受（否则 `EDIT_VALIDATION_FAILED` 结构性拒绝）；`null` 清除。序列布局 pack 合法值集 {0,1,2,4,8,16,32,64,128}（ECMA-335 II 23.11 ClassLayout 事实）；布局行成员为 `TypeDef.ClassLayout.PackingSize/ClassSize`。
- 实际落点：registry 扩展 + 逆捕获旧布局行/flag/偏移；结构验证器新增规则：explicit 布局下每个实例字段必须有偏移（重载语义，dnSpy 反编译事实）。
- 纯实现细节：pack 合法集合表位置（常量表随 IMP-009 冻结）。

### IMP-005 Marshal（field/parameter 的 marshal）

- 范围：`FieldDef.MarshalType` 与 `ParamDef.MarshalType`。
- 目标行为：`marshal: {native_type: 枚举, …可选字段}`。**生产 marshal 结构化编解码为本方案新增代码**（`EditStructuredSignatureCodec` 现无 marshal 路径——审核实证）；P03 轮次 28 的 8 类形状/13 样本证据位于 harness 测试类（`MarshalSnapshotCandidate.cs`），仅作为设计参照与非法向量来源（`SafeArray` 缺 vt 等拒绝向量在该测试类冻结）。`null` 清除。
- 实际落点：`field_add/update`、`parameter_add/update` 载荷扩展 + 逆捕获旧 marshal；schema 冻结枚举。
- 纯实现细节：可选字段缺省规则表。

### IMP-006 P/Invoke（method_add/update.pinvoke）

- 范围：`ImplMap` 行（模块名/入口名/charset/精确时间标志）与 `MethodAttributes.PInvokeImpl` 的联动。
- 目标行为：`pinvoke: {module_name, entry_name?, charset: "none"|"ansi"|"unicode"|"auto"=none, no_mangle?=false, last_error?=false, calling_convention?: "winapi"|"cdecl"|"stdcall"=winapi}`；旗标集合以 dnlib 4.5.0 `PInvokeAttributes` 实测成员为准（`exact_import`/best-fit 类旗标在 dnlib 4.5.0 无对应成员，显式排除并在 schema 拒绝）；设置时要求方法 static+extern（`PinvokeImpl` 位置语义；非 static+extern 组合结构性拒绝）；清除（`pinvoke:null`）移除 ImplMap 行并清 flag。entry_name 缺省＝方法名。module_name 不要求预存在 ModuleRef（按名惰性解析/创建，dnlib `PInvokeInfo` 事实）。
- 实际落点：registry 扩展 + 逆捕获旧 ImplMap 行与 flag。
- 纯实现细节：ModuleRef 惰性创建的归一化。

### IMP-007 Security Declaration（security_add / security_remove）

- 范围：assembly/typedef/methoddef 三种父级上的 `DeclSecurity` 行。
- 目标行为：`security_add`＝`{kind, parent:{token|"assembly"}, action: "deny"|"permit_only"|"request_minimum"|"request_optional"|"request_refuse"|"assert"|"link_demand"|"inherit_demand"|"demand"（ECMA-335/dnlib `SecurityAction` 的**本方案采用子集**；其余成员显式排除并在 schema 拒绝）, xml: 字符串}`；二进制 XML 签名由 dnlib `SecurityDeclaration` 写入器事实决定——**XML→Blob 归一路径的最小 Spike 是本 IMP 的硬前置**（证据留痕于实施记录后方可冻结 IMP-009 契约）。`security_remove`＝`{kind, parent, action}`（同 action 唯一性：dnlib 允许同 action 多行时按 index 选择，默认 0）。`xml` 长度上限＝`EditWire.MaxNormalizedOperationBytes` 同源字节预算内。
- 实际落点：registry 新 kind + 逆捕获旧行；墓碑删除逆捕获被删父级的 security 行。
- 纯实现细节：XML 规范化（去 BOM/统一换行）。

### IMP-008 字段初始数据（field_add/update.initial_data）

- 范围：`FieldDef.InitialValue`（RVA 数据）。仅 static 字段（dnlib 事实：实例字段携带 RVA 无意义）；`literal`（const）字段拒绝（与 `constant` 互斥）。
- 目标行为：`initial_data: {bytes_base64, alignment?: uint(默认 8)}`；长度上限＝新常量 `MaxInitialDataBytes = 1 MiB`（推导：操作字节总预算 `MaxNormalizedOperationBytes` 8 MiB 内含 base64 膨胀 4/3 与信封开销，1 MiB 原始数据 ≈ 1.33 MiB base64，留足余量且与既有资源量级兼容）。`null` 清除。写入后 `RVA!=0` 且重载后字节逐位一致（重载验证）。
- 实际落点：registry 扩展 + 逆捕获旧数据；结构验证器规则：static+has-data / 非静态拒绝。
- 纯实现细节：对齐写入门（压缩段对齐事实）。
