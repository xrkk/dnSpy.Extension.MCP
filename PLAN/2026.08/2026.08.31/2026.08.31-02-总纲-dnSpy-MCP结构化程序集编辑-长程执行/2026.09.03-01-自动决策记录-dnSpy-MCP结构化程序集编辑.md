## DEC-008：P03 产物 image 与实时冲突指纹分离职责

- 阶段：P03/IMPLEMENT；依据 P03 v5 §4.3/§5/§8、IMP-002/004/006/009、ACC-011/012/013/024。对实时冲突和恢复仍比较完整实时指纹；checkpoint semantic 使用已有 roundtrip 语义投影，另外比较实际输出文件全部字节的 SHA。
- 事实：隔离 r9 证明 tiny header 的 InitLocals/MaxStack 写入规范化会导致 private copy 完整指纹不一致；r11/r12 证明相同语义的源模块/发射后 baseline 的 heap 布局不同；r13 反证固定重复写出不是通用修复。
- 选择：复制时恢复 private 的原方法头属性再执行完整校验；P03 的 baseline/目标/replay/live image/export 使用唯一 `WriteCheckpointImage`，保留 metadata RIDs 与签名附加数据，重建 heap offsets；P02 Write/实时冲突守卫不替换，不忽略 SHA 的任何字节。
- 备选及不选原因：只比较语义会违反双指纹；整图替换会破坏实时 token 对象；保留每次源 heap 历史使相同 operation 重放产生不同文件；固定多写一次已被 r13 否证。未引入自动 fallback 或第二历史事实。

- 影响与代价：P03 产物 heap 偏移可以改变，额外的输出重载语义校验增加 CPU/内存；输出完整 SHA 不再继承源布局历史。原源文件零写入。此输出选择仍需所有22类操作、opaque signature/资源/旧工具执行回归覆盖，不能把当前样本通过视为任意不可信样本都保持运行行为。

## DEC-009：跨重载恢复不得复用已转属其他对象的 token

- 阶段：P03 IMPLEMENT；来源 P03 v5 §5.1/§8、IMP-002/004、ACC-011/012/013。
- 事实：r17 的删除参数 RID 是 writer placeholder；r19 的删除 GenericParam RID 已归属其他类型；dnlib PreserveRids 文档不包含 GenericParam。
- 选择：参数恢复严格识别本次 writer placeholder 并以完整记录恢复 owner/slot/name/flags，保留逆向撤回；泛型按 owner/index 的缺失槽恢复，不把另一类型的 token 行挪过来。复用旧 RID 无条件改写、整图替换、忽略完整恢复断言均不选。
- 验证：r21 x64/x86 对原对象身份/不挪用其他类型/重复恢复零变更/恢复动作撤回完整指纹通过；仍不是所有22类操作或最终验收。
- 补充实验：r22 暴露 writer 占位名称随机，尝试只规范化新生成占位名；r23 重复 image 稳定，但 r24 旧 checkpoint 完整 image 恢复仍失败。因此 DEC-008 的 image 策略及本次占位命名只保留为未完成实现，不将其升级为“已证实完整恢复”。
- 下一检验：以 r24 为不可删除的反例，验证独立于历史占位表布局的产物编码及内部操作对象定位；若改变规范性/核心恢复契约，登记 PLAN-CHANGE 并回流，不以实现细节名义绕过。
- 影响：当前 P03 的 inverse、产物编码和测试；不改变总纲范围、用户确认要求或其他 Pxx。原源文件和 dnSpy 部署均未改，代码未提交，可按归属 hunk 修正；无新增外部服务或 fallback。
