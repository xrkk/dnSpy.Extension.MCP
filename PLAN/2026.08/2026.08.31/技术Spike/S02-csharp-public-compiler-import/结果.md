# S02 C# 公开编译契约与 MCP 自有导入器技术 Spike 结果

状态：**PASS**
性质：throwaway 技术验证，不是生产实现。

## 验证问题

能否使用 dnSpy 公开 `ILanguageCompilerProvider` 取得 C# 编译结果，再由有限范围的 MCP 自有导入器
把方法/类型级变化导入私有工作副本，并最终只在程序集内保存嵌入式 Portable PDB，且不引用
dnSpy AsmEditor 内部类型或使用反射代理。

## 实际环境

- 自动化链路：AI → Win10VM MCP → PowerShell/App/FileSystem → 真实 dnSpy。
- dnSpy x64 与 dnSpy-x86 各执行一轮。
- 两轮实际选择的公开提供器均为 `dnSpy.Roslyn.Compiler.CSharp.CSharpLanguageCompilerProvider`。
- 测试源码覆盖目标字段引用、目标方法引用、异常处理、替换现有方法、增加泛型方法和泛型 `class` 约束。

## 结果

- 公开编译契约两轮均成功，编译结果包含 Portable PDB 内存载荷和 7 个 sequence point。
- MCP 自有窄导入器成功映射目标字段、目标方法、异常处理和方法体。
- 类型级导入通过增加泛型方法完成；保存并重载后方法及泛型约束存在。
- 目标 `PdbState` 转换为 `EmbeddedPortablePDB` 后由 dnlib 写入程序集。
- 重载产物识别为 `EmbeddedPortablePDB`，包含 8 个 sequence point。
- 产物目录没有生成独立 `.pdb`。
- x64、x86 分别使用目标架构夹具生成独立产物；未使用同一 AnyCPU 文件冒充两种架构。
- 两个产物均由 Python client 经 dnSpy MCP 启动真实调试会话，在编辑后的
  `Compute`（`0x06000004`）IL 0 收到 `breakpoint_hit`；暂停态栈顶帧也精确匹配
  `0x06000004+0x0`。因此嵌入式符号不仅可重载，也能驱动实际断点映射。
- Spike 程序集引用清单不包含 AsmEditor；没有反射调用内部导入器。

## S02-R1 字段与方法引用补证

阶段 7 复评发现初版样本的 `Compute` 只直接调用 `Helper`，没有直接访问 `Field`；因此初版
`field_reference_mapped=false`，同时旧 PASS 条件遗漏了字段/方法映射标志。S02-R1 已修正该
测试缺口：

- 待导入 `Compute` 现在同时直接访问目标 `Field` 并调用目标 `Helper`。
- `field_reference_mapped` 与 `method_reference_mapped` 已加入 Spike 硬性 PASS 条件。
- x64、x86 两轮导入证据中两个标志均为 `true`。
- 保存并重载后的 IL 分别解析为
  `field:System.Int32 SpikeFixture.Target::Field` 与
  `method:System.Int32 SpikeFixture.Target::Helper(System.Int32)`；这两项也已加入调试映射验证器的硬性 PASS。
- 两架构新产物均再次在 `Compute`（`0x06000004`）IL 0 收到真实 `breakpoint_hit`，最终调试状态为 idle。

初版遗漏没有被只改文字掩盖；最终证据和 PASS 判定均已重新生成。

## 实验中发现并固定的接口边界

1. dnSpy 公开 C# 编译器当前返回 `PortablePdb` 内存载荷，不直接返回内嵌格式。
2. 导入器必须把编译结果中的 sequence point 随方法体克隆到目标模块。
3. 不应把源 `PdbDocument` 手工插入目标 `PdbState.Documents`：源/目标 Portable PDB 的 Document RID 会冲突。
4. 与 dnSpy 已有写入行为一致，保留 sequence point 的文档引用，由 dnlib writer 在写符号时解析；再将目标 `PdbState.PdbFileKind` 设为 `EmbeddedPortablePDB`。
5. 编译前端与结果导入确实是两个独立边界，因此正式拆分继续保留 P05 编译前端、P06 导入和端到端编辑。

## 对正式方案的约束

S02 证明有限范围导入器可行，但不把本 Spike 的按名称/参数数目匹配当作生产级身份算法。
正式 P06 必须使用稳定签名和目标身份匹配，并逐项覆盖：

- 重载、泛型嵌套和签名歧义；
- 属性/事件访问器；
- 编译器生成类型及状态机；
- Custom Debug Information、作用域、局部变量名和异步信息；
- 非法或无法唯一映射时无副作用失败。

## 失败尝试的审计价值

- attempt 1/2：证明直接复用源 `PdbDocument` 会发生 RID/键冲突。
- attempt 3：证明自行构造 `PdbDocument` 还会遗漏 dnlib 内部初始化状态。
- 最终：删除不必要的显式文档插入，采用 sequence point 克隆加 writer 解析后通过。

所有失败证据均保留在 `../raw/*-attemptN.json`，没有被最终成功结果覆盖。
