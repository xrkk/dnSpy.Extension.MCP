## 3. AUD 逐条处理

### AUD-027：running→paused 被无条件标为 manual

- 处理结论：同意。
- 风险：高。
- 理由：v13 的 generic paused 分支忽略 `DbgRuntime.BreakInfos`，与已存在的 breakpoint/exception/step 事件及上游稳定 message kind 冲突；scheduled/issued pause 与非 manual stop 碰撞时还会伪造请求因果。
- 证据：REQ-DYN-004/005/008、RACC-DYN-002/004/005、CON-DYN-003/004/013；v13 第 3.2/3.5/3.6 节；EVD-API-011；新增 EVD-API-012 的三个固定 blob。
- 实际修改：方案 1.2 新增 EVD-API-012；3.2 增加完整 BreakInfos 快照、`exception > breakpoint > step > entry > process > manual > unknown` 封闭优先级和 original ordinal；API-DYN-006 增加实际 reason、`request_effect=caused_pause|state_satisfied`、cause identity；EVT-DYN-010 增加 unknown 并固定先于 EVT-DYN-014/owned EVT-DYN-013/current-step EVT-DYN-015；同步修改 3.6、IMP-004/005/006/007、ACC-007/008/012/014/028、版本记录和审核重点。
- 不修改边界：不新增事件 ID，不修改 initial break_kind 的 process/module_cctor_or_entry/entry 映射，不把 unowned breakpoint伪造成 MCP breakpoint，不以 control_epoch 伪造上游 token。
- 最小闭合条件：已满足。无 pending control、P2 scheduled/issued 与 breakpoint/exception/step 碰撞、issued+Break manual 正例、settled late Break、foreign step、多原因 ordinal均有实际命令、精确 response/reason/request_effect/pause_epoch/identity/event order/callback/cache/queue 通过失败边界。
- 复审请求：定向复核 3.2/3.5/3.6 的原因仲裁及 ACC-007/008/012/014/028；公共 response/event 语义变化局限于 AUD-027 的实际 diff 和受影响既有通过项，不改变规范性来源含义、方案范围、总体架构或权限归属。

### AUD-028：目录/child handle 不能冻结 child-name 集合

- 处理结论：同意。
- 风险：高。
- 理由：CreateDirectory2A 官方示例直接证明 directory handle 不阻止新增 child；v13 在 scan 后、CreateDirectory/CreateNew/commit 前仍有 external sibling 竞态，不能维持“当前 admission 注入后零写”保证。
- 证据：REQ-DYN-010/011、CON-DYN-008/009、RACC-DYN-007、API-DYN-001/024、IMP-009、ACC-019；EVD-OS-001 的 CreateFileW/CreateDirectory2A 一手契约。
- 实际修改：CON-DYN-008 把信任保证固定为“current admitted closed write plan 可完成，next write admission 重新枚举并 TARGET_MISMATCH”，禁止声称 namespace lock；API-DYN-001.artifact_policy 明示 external-child race。active session child 从 commit 起持有 no-write/no-delete-share handle，terminal 时把目录、ledger 和全部 handle 原子转移为 current-process known_retained retention lease并保持到进程退出；后续只复核 metadata/name-set，禁止重复重哈希最多 8 GiB。ACC-019 新增 scan前及 pre-CreateDirectory/pre-CreateNew/pre-commit 三个 scan后 barrier，分别断言 current/next admission 的精确 tree/response。
- 不修改边界：跨重启仍全部 stale_untrusted；零自动删除、零 DELETE access、CreateNew、防覆盖、配额和人工退出方式不放宽；外部进程仍可造成拒绝服务。
- 最小闭合条件：已满足。三个 scan后 barrier 固定允许/禁止的 extension-owned delta、下一 admission、ledger/handle/hash、capability disclosure 与恢复步骤；既有 child 的写/删/换由 retention handle 的 sharing violation 另行证明。
- 复审请求：定向复核 ArtifactRoot threat/trust 子契约、API-DYN-001 capability、IMP-009 和 ACC-019；变化仍位于原有 REQ-DYN-010/011、CON-DYN-008/009 和 IMP-009 范围内，未改变 ArtifactRoot 权限/隔离归属、方案总体范围或迁移策略。

### AUD-029：全量哈希缺少时延、取消和队列释放边界

- 处理结论：同意。
- 风险：中。
- 理由：v13 每次写 admission 最多读取并哈希 8 GiB，且所有副作用共用 FIFO；容量上限不能证明终止及时性，queue wait、取消、store lock/cache slot 结算均无机械边界。
- 证据：REQ-DYN-004/010/014、CON-DYN-008/009/013、RACC-DYN-004/007/009、API-DYN-024、IMP-009/011、ACC-019/022；EVD-OS-001 的 share mode 与 CancelIoEx completion 语义。
- 实际修改：以 process-lifetime retention handle 取消 retained bytes 全量重哈希；把 root/session/全 store 子项上限固定为 128/4096/4096。增加 30000 ms `ArtifactOperationRecord`、≤1 MiB I/O chunk、2000 ms control cancellation grace、`IArtifactIo` seam、CancelIoEx final completion 检查和 response gate。副作用队列固定为 8 control + 56 general、总量 64，control 在 coordinator boundary 优先。CreateNew 前 timeout/cancel 零 tree；CreateNew 后仅可留下一个 ledger-known `aborted_owned` partial child，无 manifest、零自动删除，迟到 completion 不得继续写或改响应。API-DYN-024 增加 TIMEOUT/INVALID_STATE；ACC-019/022/028 固定 near-limit、真实 Windows volume、29.999/30.000 秒、取消三完成态、terminate 抢占和全部资源结算。
- 不修改边界：不引入时间缓存、后台 cleanup、自动删除、外部 helper、fallback 或跨进程账本恢复；512 MiB/1 GiB/8 GiB 字节配额不放宽。
- 最小闭合条件：已满足。方案写明工作目录和现有 case 外部命令、输入 seam、30 秒/2 秒精确阈值、response/tree/hash/ledger/store/general/control/cache/reservation结果及通过失败边界；真实 Windows volume failure 阻断 build/release。
- 复审请求：定向复核 queue policy、artifact state/partial ledger、API limits、IMP-004/009/011、ACC-019/022/028；双 lane 和资源结算属于既有 coordinator/artifact store 内部契约，IMP-004/009/011 的依赖与顺序未改变，不构成总体架构或方案依赖图变化。
