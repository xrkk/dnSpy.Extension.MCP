## 3. AUD 逐条处理

### AUD-027：同意

- 风险：高。
- 层级：当前方案公共响应与实施契约，不改变上层需求或 dnSpy 权限归属。
- 理由：v14 的 `issued + Break → caused_pause` 在 stock API 下不可证实；P1 的迟到 Break 可以在 P2 issued 后产生完全相同的观察。
- 实际修改：方案 1.2 EVD-API-012、3.2 pause cause/response gate、3.5 API-DYN-006、3.6 pause transition、IMP-004、ACC-007/008/028、版本记录与审核重点。
- 固定结果：API-DYN-006 reason 保留七值实际分类，request_effect 收缩为常量 `state_satisfied`；任何 stock API 路径都禁止 `caused_pause`。P1 late Break 在 P2 issued 后到达时，P2 只返回 `reason=manual,request_effect=state_satisfied`，P1 已封口响应、事件、cache 与 lane 均不改写。
- 证据：EVD-API-012 的上游 blob；ACC-007/008/028 新增无 token adapter、P1/P2 barrier、response/event/cache/callback/lane 精确断言。
- 最小闭合条件：满足。
- 复审请求：定向复核上述位置是否彻底移除 causal promise，并运行/审查 P1 late Break→P2 issued 反例；无需重审未受影响的状态观察、cause priority 与 detail event 顺序。

### AUD-029：同意

- 风险：中。
- 层级：当前方案 artifact cancellation 的资源、数据一致性、队列和验收契约；不改变 ArtifactRoot 上层安全目标。
- 理由：CancelIoEx 不提供两秒最终完成保证；v14 同时要求两秒释放资源和等待最终 completion，无法同时实现。
- 实际修改：方案 EVD-OS-001、CON-DYN-009/013、CON-DYN-008 全局 store 规则、3.2 control grace、API-DYN-001/024、IMP-004/009/011、ACC-019/022/028、版本记录与审核重点。
- 固定结果：2000 ms 只限制 control 等待。grace 后仍 pending 时，artifact request/cache/general slot 和 store lock先唯一结算，record 进入 `canceling` 并建立全局 store barrier；OVERLAPPED、buffer、file handle、完整性/配额 reservation 保持到 normal、ERROR_OPERATION_ABORTED 或其他 error 最终 completion。finalizer 使用同一 handle 取得最终 identity/length并从头计算未 retained partial 的 SHA-256，写入唯一 `aborted_owned` ledger；对账失败则 session `stale_untrusted`。后续 control 与非 store 请求继续，新 store mutation 零副作用 `INVALID_STATE`，terminal 只标 `terminal_pending_artifact`，最终对账后再转 known_retained/stale。扩展进程先退出时由 OS 回收资源，下一进程把 partial 视为 stale_untrusted。
- 证据：EVD-OS-001；ACC-019 的 1999/2000/3000 ms、三种最终 completion、response/file/ledger/resource/store/cache/lane/terminal 时间线；ACC-022 不再把真实 volume 的两秒 I/O completion 当发布门禁；ACC-028 跨三协议验证能力字段和分离生命周期。
- 最小闭合条件：满足。
- 复审请求：定向复核 canceling state、资源持有与释放、后续 control/store/cache 行为和三类 final completion；无需重审 v14 已通过的 external-child、retention、配额和零删除规则。
