## 4. 实施步骤（IMP）

每步先写幂等标记再执行; 恢复时按标记与实测文件状态核对, 已完成只补记。所有 VM 侧产物落在 `E:\dnspy-scenario\` 或可逆网络规则内。

- **IMP-101 传输与产物核验**
  在 `E:\dnspy-scenario\stage\` 建立中转区; 启动临时 http 服务, 上传: ① EF-03 net10 宿主目录打包（tar/zip, 传后 VM 解包至 `net10\app\`）; ② `dist/dnSpy.Extension.MCP-net48.x.dll`、`dist/dnSpy.Extension.MCP-net10.0-windows.x.dll`; ③ EF-11 初始样本。VM 侧对每个文件计算 sha256 并与 Linux 侧清单比对, 全部一致才算完成; 记录两侧 hash 对照表。关闭 http 服务（账本记录时段）。
- **IMP-102 net48 部署**
  复制 `C:\Tools\dnSpy` → `E:\dnspy-scenario\net48\app\`（剔除 `bin\Extensions\dnSpy.Extension.MCP\*.bak*` 与 `*.pre-*.dll` 历史副本）; 覆盖 `bin\Extensions\dnSpy.Extension.MCP\dnSpy.Extension.MCP.x.dll` 为 dist net48 产物并核验 sha `ce13450a…`; 按 D-08 写便携设置 `net48\app\dnSpy\dnSpy.xml`（Port=15100）; 生成 `net48\deployment-manifest.json`（逐文件 path+size+sha256, 模式同 deploy-r15.ps1）。
- **IMP-103 net10 部署**
  解包宿主至 `net10\app\`（dnSpy.dll 位于根）; 建 `net10\app\Extensions\dnSpy.Extension.MCP\` 放 dist net10 DLL（sha `c9de721b…`）; 写便携设置（Port=15101）; 生成 `net10\deployment-manifest.json`; 记录启动器 `C:\Tools\dotnet10-x64\dotnet.exe dnSpy.dll`（工作目录 = app 根）。
- **IMP-104 网络规则（可逆）**
  `netsh http add urlacl url=http://192.168.204.240:15101/ user=Everyone`（15100 已存在, 幂等校验）; `New-NetFirewallRule -DisplayName dnspy-mcp-scenario -Direction Inbound -Protocol TCP -LocalPort 15100,15101 -RemoteAddress 192.168.204.1 -Action Allow`; 撤销命令（`netsh http delete urlacl …15101/`、`Remove-NetFirewallRule -DisplayName dnspy-mcp-scenario`）写入 `evidence\network-rules.json`。
- **IMP-105 启动与 `/health`（ACC-037/038 动作一）**
  分别启动两实例（Start-Process 记录 PID/命令行/启动 shell 环境快照——证明启动上下文无 `DNMCP_TEST`）; 从 Linux `GET http://192.168.204.240:15100/health` 与 `:15101/health`, 保存原始响应至 `evidence\{net48,net10}\health.txt`; 非 200 或不可达按阻断边界处理。
- **IMP-106 `tools/list` 快照与三族计数对照（ACC-037/038 动作二）**
  从 Linux 以 `dnspy_mcp` 客户端（HTTP 形态）对两实例执行 initialize + `tools/list`, **保存原始 JSON 响应**至 `evidence\{net48,net10}\tools-list.json`; 生成 `counts.json`: 通告工具总数、三族分类计数（静态/调试/编辑; 归类成员清单在实施时从代码生成——静态 = `McpTools.cs GetAvailableTools` 名单, 调试 = 恒通告 `debug_capabilities` + `AdvertisedSessionTools` 21 名单（EF-09）, 编辑 = `EditToolProvider.ProductTools` 17 名单, 成员清单全量写入 counts.json 供审计）、`*_test_*` 计数（预期 0）。**判定为二分**（AUD-201 闭合）: ① 硬失败——通告为空、含任何 `*_test_*`、或**调试生产面整体缺失**（会话工具通告数 = 0, 即仅启动式生产门未生效, 如 net10 实例只回 32 静态 + debug_capabilities + 17 编辑 = 50 项时）; ② 其余非零偏差（个别工具缺失/多出、总数与 71 不等）——在快照记录标注"触发 F-02 重裁决评估（重算矩阵/排查缺失原因）", 不作硬失败。
- **IMP-107 生产配置核验（ACC-039）**
  记录两实例进程命令行与启动环境（`evidence\{net48,net10}\env-proof.json`）; 对两实例直呼 `debug_test_spy` 与 `edit_test_clock`, 保存原始响应（预期: 域错误包 `CAPABILITY_UNAVAILABLE` / `EDIT_CAPABILITY_UNAVAILABLE` 类, 非执行、非 Unknown tool、非 isError 之外的文本）。
- **IMP-108 样本基线与 ArtifactRoot 清单（ACC-040）**
  对 `samples\` **递归**（含子目录, 清单记相对路径）全部文件计算 SHA-256 生成 `evidence\samples-baseline.json`（逐文件 path+size+sha256）; 记录 `artifacts\` 初始内容清单（预期空, 同为递归口径）。基线文件即 P02 复位例程 hash 管理组件（ACC-043 前置）的初始输入。
- **IMP-109 证据归档与核验记录**
  将 `evidence\` 全部产物下载回 Linux, 连同 Linux 侧传输 hash 对照、命令与时间戳, 写入核验记录 `PLAN/2026.09.29/2026.09.29-07-核验记录-P01-部署重建与覆盖基线.md`（实施时创建, 编号以当日实际顺延为准）; VM 侧 `evidence\` 保留原位。至此 P01 产出齐备: 部署清单与核验记录（IMP-102/103 manifest + 105..109 证据）、两份 tools/list 快照、初始 hash 基线清单。

## 9. 实例生命周期与后续 Pxx 契约

- P01 完成后两实例保持运行（专用非交互实例, 见 `docs/deployment-dynamic-debugging.zh-CN.md` §1 前提: 无人操作其 UI、不装其他会调 `DbgManager.Start` 的扩展）; P02 冒烟、P03/P04 执行均使用本方案部署。
- 后续 Pxx 连接契约（P01 固定, 下游不得另起炉灶）: net48 = `http://192.168.204.240:15100`（MCP 端点同基址）, net10 = `http://192.168.204.240:15101`; 免 Token, 仅 192.168.204.1 直连; 样本目录 `E:\dnspy-scenario\samples`, ArtifactRoot `E:\dnspy-scenario\artifacts`。
- VM 重启或实例退出后: 按同一启动命令重启（便携设置已持久化 `DedicatedDebugInstanceAcknowledged=true`, `EffectiveDebugLaunch` 每次启动重新冻结, 行为不变）; 重启不改变部署文件与基线清单, 样本/ArtifactRoot hash 基线继续有效; 若部署文件被外因改动, 以 `deployment-manifest.json` 复核后再用。
- P01 的产物基线（samples-baseline.json / artifacts-initial.json）是 P02 复位例程组件的初始数据; P03 增补样本时按 ACC-047 增补基线, 不重跑 P01。

## 10. fallback 声明

本方案无运行时 fallback 机制; §8 恢复路径为工程处置步骤而非行为降级。D-04 免 Token host-only 模式是部署配置选择, 不是认证降级（CIDR 仍强制, 401/403 语义不变）。
