**阶段 5: 实施和逐条验收**

- 实施前证明方案至少有一轮已引入第三方审计, 当前版本由匹配审计及处理记录或绑定首次审核祖先的作者自评闭环支持, 状态为 `已审核, 可以实施`, 无待复审项. 复核来源、审核基线漂移、IMP/ACC、任务边界和受保护现场.
- 定位已有匹配实施记录; 找到时沿原路径继续, 未找到时创建 `YYYY.MM.DD-NN-实施记录-{方案名}.md`. 记录方案、来源、审核闭环、实施授权、分支、基线、边界和轮次. 为全部 IMP/ACC 追加状态、落点、验证动作、退出码或等价结果、摘要和持久证据. 状态只允许 `未开始 -> 进行中 -> 通过/不通过`; 真实阻碍可为 `被阻断`, `不适用` 必须有机械条件和证据.
- 按 IMP 修改代码、配置、数据、测试和文档. 修改前记录全工作区路径级状态和任务边界内 diff; 全工作区状态只用于归因和保护, 不要求清洁. 每组修改后运行最小直接验证并修正, 最终执行全部 ACC, 覆盖正常、异常和边界路径. 验证失败先对照实施前状态和当前 diff 归因: 范围外既有且未恶化的问题只记环境观察; 有证据由本次改动引入时按受影响 ACC 处理; 无法归因且没有等价证据时只阻断受影响 ACC. 普通困难、测试失败、实现复杂和待办不是停止理由.
- 对实际 diff 逐文件/hunk 核对方案依据. 修正无依据改动、额外 fallback、失效旧路径以及可归因于本次实施的回归和测试副作用. 方案外事实分类为需求变化、方案契约变化、纯实现细节或无关问题; 纯实现细节最小处理并记录, 契约变化回流方案、自评和适用的审核路线, 实施授权保持进行中. 实施暂停回流后若选择定向复审, 必须先持久化阶段 4 定义的完整定向复审请求范围, 第三方再输出并记录本轮实际范围; 范围闭环前不得恢复实施.
- 按本入口的审核与执行协议确定实施执行方. 主会话负责实施门禁、实施记录、逐项验收和提交, 委派不转移这些责任.
- 实施因真实阻碍暂停时, 当前回复必须按执行顺序直接列出阻碍消除步骤; 每步写明执行方、动作、所需输入或权限和完成判据, 最后写明解除后恢复的检查点. 持久化记录路径只作补充引用, 不能替代步骤正文.
- 只有全部必需 IMP/ACC 通过, 不适用项有证据, 不存在未开始、进行中、不通过、被阻断、待复审或可归因于本次实施的越界、回归破坏、未清理副作用, 且范围外既有失败和 dirty 状态已识别并保持隔离, 才能宣布完整落地. 只暂存并提交可机械归属的文件/hunk和实施记录, 核对提交 SHA、文件、diff 和映射; 无法安全分离时不提交.
