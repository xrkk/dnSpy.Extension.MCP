## 发现（AUD）

- **AUD-201〔中〕ACC-037/038"调试生产面缺失"失败边界被实效弱化**
  问题: 子方案 §5 将 ACC-037 失败边界写为"调试生产面缺失（22 族为 0 且无偏差说明）", 而 IMP-106 规定"任一族计数与 32/22/17 不一致: 在快照记录标注…不作硬失败"且标注为流程自动产物。两者叠加后, 只要按流程执行, 任何计数偏差（包括调试族整体缺失）必然带有偏差说明, "且无偏差说明"条件永假, 失败分支成为死条款; 而总纲 ACC-037/038 明列"调试生产面缺失"为失败边界, F-02 并明确"部署须启用仅启动式动态调试生产门——未启用时调试会话工具不通告…覆盖全集将缺失调试生产面"。§7"语义弱化数: 0"的声明与该差距不符。
  反例证据: 若 net10 实例 `DedicatedDebugInstanceAcknowledged` 未生效（如设置快照未采纳、gate 冻结为 false）, 按 `DebugToolProvider` 逻辑 tools/list = 32 静态 + 1 `debug_capabilities` + 17 编辑 = 50 项, 调试族计数 1≠22 → IMP-106 判"标注重裁决评估, 不作硬失败"; §5 失败条件"22 族为 0"不命中（计数为 1）→ ACC-038 在调试生产面缺失 21/22 的状态下走"通过（偏差标注在案）"路径, 与总纲失败边界冲突, 且该坏基线将流入 P02..P04。
  证据: 子方案 §5 ACC-037 行、IMP-106、§7; 总纲 §3 F-02、§5 ACC-037/038 失败边界; `Debugger/DebugToolProvider.cs:53-54`（gate 关闭时会话工具全部不通告）与类注释（debug_capabilities 恒通告）。
  受影响通过项: §5 ACC-037/038 判定单元、§7 弱化计数、IMP-106 判据。
  最小闭合条件: 在 IMP-106 与 §5 写明二分判据——"调试族仅剩 `debug_capabilities` 或会话工具（21 员）全缺失 ⇒ 硬失败（部署生产门未生效, 无论有无偏差标注）; 其余非零数值偏差 ⇒ 标注 F-02 重裁决评估, 不作硬失败"（或语义等价表述）, 并同步 §7 计数。

- **AUD-202〔低〕EF-09 对调试生产面 22 的归属表述不精确**
  问题: EF-09 写"调试生产面 22（`AdvertisedSessionTools`）", 而 `AdvertisedSessionTools` 数组实数 21（`DebugToolProvider.cs:314-321`）, 22 = 恒通告 `debug_capabilities` 1 + 21 会话工具（类注释 9-12 行明示"tools/list always gains exactly debug_capabilities; the remaining 21 tools are advertised only while the frozen gate is active"）。IMP-106 已声明"含 debug_capabilities 与 AdvertisedSessionTools 的实际归属, 以代码为准"且成员清单全量写入 counts.json, 流程可自纠; 但 EF-09 是归类依据事实表, 实施者若按括注把 21 当期望值或漏归 `debug_capabilities`, 会产生虚假偏差标注（非硬失败, 污染计数对照记录）。
  证据: 子方案 §2 EF-09、IMP-106; `Debugger/DebugToolProvider.cs:9-12`（类注释）、`:314-321`（数组 21 项实数）; 总纲 §8"生产面 22"无此归属括注。
  受影响通过项: EF-09、IMP-106 归类输入。
  最小闭合条件: EF-09 括注改为"22 = `debug_capabilities`（恒通告）+ `AdvertisedSessionTools` 21"。

- **AUD-203〔低〕IMP-108 样本基线的递归口径未定义**
  问题: IMP-108 写"对 `samples\` 全部文件计算 SHA-256", 未明确是否递归子目录、path 字段是否相对根。D-06 初始内容含 `dist/p01-fixtures/`（目录形态三件套）, 若实施者以子目录形式上传, 非递归枚举将漏 3 个文件, ACC-040"现有全部样本"的逐文件基线不完整, 且该缺口会传导至 P02 复位例程的初始输入。
  反例证据: 设 `samples\p01-fixtures\TestIL.dll` 等以子目录存在, 非递归 `Get-ChildItem` 只得根级文件, `samples-baseline.json` 缺 3 条, ACC-040 判据"清单存在且逐文件含路径+hash"形式满足而实质漏项。
  证据: 子方案 IMP-108、D-06、EF-11（p01-fixtures 为目录）; 总纲 ACC-040"对 VM 样本目录现有全部样本"。
  受影响通过项: IMP-108、ACC-040 证据完整性。
  最小闭合条件: IMP-108 补一句"递归枚举含子目录, path 记相对 `samples\` 根路径"。
