## 4. 账本 JSONL schema（ACC-041 冻结内容）

每行一个 JSON 对象, UTF-8, 追加写; 顶层字段:

```json
{"schema_version": "dnspy.scenario.ledger.v1", "kind": "meta|call|assert|reset|result",
 "scenario_id": "S-<族>-<NN>", "batch": "net48-fam-01|net10-sample|net10-rerun-*",
 "step_seq": 0, "timestamp": "<ISO8601 毫秒>"}
```

- `meta` 行（每情景首行）: `{"declared_tools": [...], "tfm": "net48|net10", "docstring": "..."}`。
- `call` 行: `{"tool": "...", "request": {...}, "response_summary": {"is_error": bool, "error_code": str?, "content_head": str(≤200 字符)}, "duration_ms": n, "outcome": "ok|unexpected_error|expected_error"}`——`expected_error` 仅当该调用被 `expect_error` 预告; 响应全文不入账本（8MiB 上限, EF-204）, 摘要入账, 全文按需存 ArtifactRoot 由 meta 行指向。
- `assert` 行: `{"step_seq": <关联调用序>, "grade": "strong|weak", "verdict": "pass|fail", "expected_error": bool, "detail": "断言表达式摘要 ≤200 字符"}`。
- `reset` 行: `{"check": "edit_idle|debug_idle|session_closed|samples_hash|artifacts_inventory", "verdict": "pass|blocked", "detail": "..."}`; 失败分类字段 `failure_class`: `strong_assertion|unexpected_error|reset_blocked|env_blocked|collection_error`（RACC-002 三类处置的映射在规范文档定义: 规格缺陷←strong_assertion/unexpected_error 之用例侧; 产品缺陷←unexpected_error 之产品侧; 环境问题←env_blocked; 判定归 P04 处置循环, 账本只记原始类别）。
- 情景终态行 `result`: `{"outcome": "pass|fail|blocked", "failure_class": <如上, pass 时省略>, "strong_asserts": n, "weak_asserts": n, "unexpected_errors": n}`（判定语义 = F-03: 强断言全过且无未预期 error 才 pass）。

覆盖矩阵口径（写入规范）: 矩阵单元 = 工具 × 该工具出现过的 call 行情景 ID 去重集合; `batch` 以 `net10-sample`/`net10-rerun-*` 为不计入矩阵的复跑批（F-01/AUD-111）。

### 4a. 异常路径记账时序契约（AUD-303 冻结五点）

1. **预告先于调用**: `expect_error(tool, code)` 返回上下文管理器, 进入时在录制代理登记预告, **必须先于**该工具调用发生; 追加式账本不容事后补标记——调用发生时无预告且 isError/抛出 → 记 `unexpected_error`, 事后预告无效。
2. **error_code 提取**: `call_tool` 出错抛 `ToolCallError`, 其 text 为域错误 JSON（P01 直呼证据实证: `{"error":{"code":"CAPABILITY_UNAVAILABLE",...}}`）; 代理捕获后尝试 `json.loads(text)` 取 `error.code`（回退: 顶层 `code`; 再回退: `null` + `content_head`=text 截断）。
3. **传输层错误归属**: JSON-RPC 协议错误/HTTP 非 200（`DnSpyProtocolError`/`DnSpyHttpError`/连接错误）记 call 行 `outcome=transport_error`, 与工具级 isError 分离; 处置分类学 env_blocked。
4. **expect_error 的断言等级**: 预告命中后代理自动写 assert 行, `grade=strong`（预期错误码匹配是关键数据传递点判定）。
5. **result 行 finalizer 责任**: fixture teardown 的 finally 块**必然**写 result 行——情景体正常结束、断言失败、未捕获异常、乃至复位例程自身 BLOCKED, 均以终态行落账（未捕获异常时 `outcome=fail, failure_class=collection_error`; 复位 BLOCKED 时 `outcome=blocked, failure_class=reset_blocked`）。

### 4b. 基线与清单文件机制（AUD-304）

- **样本基线**: 权威件 = P01 产出 `E:\dnspy-scenario\evidence\samples-baseline.json`; 仓库侧运行副本 `tests/scenario/baselines/samples-baseline.json`（P02 建立时同步自权威件, 记录来源与同步时间）; 复位例程经 vmbridge 对 VM 实测 hash 与仓库副本比对。**更新流程**: P03 按 ACC-047 增补样本后, 由 P03 生成增补后基线（旧清单 ∪ 新样本）写回两处并在增补记录中留 diff 证据; 复位例程对"基线外新文件"判 BLOCKED（fail-safe, 解除责任在 P03 补基线, 不在例程侧放行）。
- **ArtifactRoot 运行清单**: `tests/scenario/baselines/artifacts-inventory.json`（初始 = P01 artifacts-initial 空清单）; 复位例程每次核对后**追加式**更新（仅允许新增条目: path+size+sha256+首次见到的情景 ID）; 发现已记录文件被改动/删除 → BLOCKED。
- **装载规则**: 两文件缺失时复位例程判 `env_blocked`（不允许无基线运行）。
