## 3. 熔断根因反例复核

对 Spike 15 条转换逐一复核：

- 线性化前 cancel：temp absent/cleanup success 得到 pre-state idle；cleanup failure 得到 cleanup recovery。
- verified post-live：finalize success 得到唯一 checkpoint；failure 得到 checkpoint-finalize partial。
- forward failure：inverse success 后按 cleanup 进入 pre-state idle或 cleanup recovery；inverse failure 得到无 recovery unknown，temp residual。
- partial recovery：retry 只 finalize；undo inverse success 后清理，inverse failure 转 unknown。
- cleanup recovery：只删除绑定 temp；成功 idle、失败保持。
- process restart：清掉进程内事务/recovery/unknown，重新加载源；磁盘 residual 仍不可信、计量且不自动删除。

互斥性：checkpoint/partial 仅在 `live=post_verified`；unknown 的 product allowed actions 只有 query；cleanup state 的 action 只有 cleanup_temp；forward failure 不能 retry；session close 在每条路径只释放 owner/slot，不改业务结果。

可观察性：五种 surface 分别由 edit_status/history、live fingerprint、head/package identity、temp/residual file ID 和 allowed actions 区分。旧 request terminal 不参与跨 session oracle。测试 seam 只在 unknown 阻断证据保存后清理 live fixture，不作为产品动作。

结论：`AUD-004` 的方案抽象根因已经被 Spike 和 v3 消除；没有用新增高风险能力掩盖缺口。

- 安全/非目标：不增加 raw edit、AsmEditor、数据库、任务系统、认证包装、后台清理、远程 unknown 修复、跨会话 terminal、copy-over 或自动接纳。
