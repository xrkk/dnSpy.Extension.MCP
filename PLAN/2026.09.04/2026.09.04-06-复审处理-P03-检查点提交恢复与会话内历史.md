### AUD-004：同意复开并修改

- 原因：v1 把“越过第一项 live mutation”绝对化为 checkpoint 或 PartialCommit，但 P02 的 forward/inverse 故障是可达事实。forward 失败且 inverse 成功时已回 pre-live，不能诚实地产生 checkpoint-finalize partial；inverse 失败必须进入 `live_state_unknown`。
- 修改位置：P03 v2 §4.1、§4.2、§4.4、§6、§7、§8.1、ACC-019、ACC-024、版本记录与审核重点。
- 唯一优先级：session close 只撤销 owner/session，不能抢占已取得串行权的操作终态；只有 live 成功才进入 checkpoint 或 finalize partial。forward 失败且 inverse 成功时终止事务、保持 pre-live/head/package，temp 删除成功回 idle并保留 rolled-back terminal；删除失败进入 `committing + aborted_temp_cleanup`。inverse 失败进入 `live_state_unknown`，旧 head/package 不变，temp 绑定在 unknown 上下文，待 P02 显式 live 恢复后再清理。
- 单一恢复：`aborted_temp_cleanup` 与 checkpoint-finalize PartialCommit 是同一协调器中互斥的 recovery union，不是第二事务状态；它只允许 `edit_recover(action=cleanup_temp)`，核对 pre-live/head/package 及 temp path/file ID/length/SHA 后仅删除 temp，永不 forward/inverse/finalize/checkpoint。cleanup 失败保持同 recovery，不能误报 idle。
- 验收：ACC-019 新增 first-mutation 后 forward failure × inverse success/failure × cleanup success/failure，并在 x86/x64 对 DELETE、流断开、listener Stop 读回 state/recovery/terminal/live/head/package/temp/file ID/session count；ACC-024 对五种 operation kind 纳入 forward/inverse/cleanup 故障和 cleanup recovery 幂等。
- 最小闭合条件：已满足。不新增产品状态，明确了 live success、forward rollback、inverse unknown 和 cleanup failure 的互斥终态及可用动作，并收窄 v1 绝对描述。

### AUD-005：继承关闭

同意复审“关闭”结论。v2 把相同 live/inverse/cleanup 优先级明确复用于 Undo/Redo/exact restore/migration；只有 live 成功+finalize 失败才进入对应 operation kind partial。原 navigation/migration 闭合未被拆散。

## 3. 实际差异、影响与全局不变量

v1→v2 实际差异：

1. 方案版本升为 v2，并记录 v1 blob；
2. `committing` 新增唯一可跨调用的 `aborted_temp_cleanup` 投影，未新增状态枚举值；
3. `edit_recover` 增加严格限定的 `cleanup_temp` action，新增 `EDIT_CHECKPOINT_CLEANUP_FAILED`；
4. commit §3/§6 从“forward失败后事务可继续”改为事务终止并按 inverse/cleanup 得到唯一终态；
5. 用七行优先级表取代“越线必 checkpoint/partial”的绝对规则；
6. recovery 由互斥的 checkpoint-finalize partial 与 aborted-temp cleanup 组成；
7. navigation/migration 复用相同优先级；
8. ACC-019/024 纳入复合故障矩阵和精确证据。

受影响既有通过项：`RACC-019`、REQ-007/017、CON-005/007/020、IMP-003/004/008/009、ACC-019/024，以及 commit/navigation 的 close/live/recovery 交界。未受影响继承项：source identity、ZIP/capacity、history tree、三态分类、原子导出、legacy 迁移、Pxx 边界、双 TFM/双架构及文档共同回归。

全局不变量：单一协调器与全进程单事务；源和旧 package 不覆盖；只有 live 成功才能创建目标 checkpoint 或 finalize partial；forward 不重放；未知 live 阻断；temp 只能按 file ID 删除；所有 recovery 互斥且阻断新编辑/导出；无数据库/后台恢复/copy-over/自动接纳；不实施 P04-P09。
