## 5. 审核意见

### AUD-001：源 family 与 active-lineage 的规范身份未冻结

- 风险级别：**高**
- 引用：`REQ-010`、`REQ-025`、`CON-004`、`CON-009`、`RACC-025`；`OUT-003/P03`；`IMP-002`、`IMP-006`；`ACC-012`、`ACC-025`；方案 §4.3、§5.1、§8.3（行 131、163、227-229）。代码证据：`EditWorkspace.Create` 当前以 `assembly_name` 加可选 MVID 选择 live module，`SourceResult` 暴露 assembly/module/path/file SHA/MVID/fingerprint，但不存在持久 family key 算法。
- 反例：同一路径的文件被替换但 assembly name/MVID 恰好复用；同一文件被 Save As 到不同路径；两个字节相同副本同时加载；无 `Location` 的模块；Windows 路径大小写/规范化变化；已有多个 superseded leaf 而调用者省略 `superseded_lineage_id`。若 family 取路径会拆错谱系，取 SHA/MVID 会把替换或副本并错，取 assembly name 会直接碰撞；不同实现都能声称符合当前文字。
- 影响：`edit_begin` 可能绑定错误 head、漏报 UI 偏离或错误返回冲突；`edit_accept_live` 可能取代错误谱系；旧 `save_assembly` 的“无历史且 live 未修改”也没有可判定的参照。这使 `RACC-025` 语义弱化，并使 `ACC-012/025` 的结果不可跨重启和多模块场景复现。
- 最小闭合条件：冻结规范 `source_family_id` 的输入字段、规范化/哈希算法和版本；分别定义 pathless、路径变化、磁盘替换、相同副本、多 loaded module、多 leaf、显式 `superseded_lineage_id` 的选择/拒绝规则；package schema、history/status/accept 响应必须暴露足以复核但不泄露越权路径的身份摘要。
- 受影响的通过项：需求保真 `RACC-025`；方案自称完整的 `IMP-002/006`、`ACC-025`，以及 `ACC-012` 的“同一源谱系”。
- 复审证据：identity 规范与 schema 常量的单一来源；上述反例逐项 fixture；进程重启后相同解析；每例的候选集合、选择/冲突错误、live/head/package 前后身份和零副作用证据。

### AUD-002：临时包名直接绑定任意 `request_id`，路径安全与唯一性不闭合

- 风险级别：**高**
- 引用：`REQ-007`、`REQ-024`、`CON-009`、`CON-024`；`OUT-003/P03`；`IMP-001/002/003/005`；`ACC-024`、`ACC-029`；方案 §4.1、§5.1（行 112、158-161）。代码证据：P02 契约的 `request_id` 只是 1..128 字符字符串，无安全文件名 pattern；协调器直接读取其字符串值。
- 反例：合法 schema 输入可包含 `..`、`/`、`\\`、冒号、尾点/空格、设备名或只在 Windows 规范化后碰撞的两个 ID。按字面追加可能越出目标目录、产生 ADS/设备名或别名碰撞；临时再清洗会把两个幂等身份合并；直接拒绝又没有已冻结的错误和 schema 语义。句柄所有权不能替代“如何从不可信 ID 得到路径组件”的决定。
- 影响：prewrite/recover 可能定位错误 temp、覆盖或误删其他请求对象，`retry_checkpoint` 的 temp identity 不再可靠；严格 schema 接受的输入与运行时路径规则不一致。
- 最小闭合条件：不得把调用者原文作为路径组件；冻结无碰撞的安全映射（例如服务端随机 temp identity，或带域分隔的 request-id SHA-256）及其长度、重试查找、所有权和错误语义；对最终路径执行 handle-based 同目录/非重解析验证。
- 受影响的通过项：`IMP-001/002/003/005`，`ACC-024/029`，以及 package 原子更新安全结论。
- 复审证据：schema/manifest 中的安全 temp identity；Windows 保留名、分隔符、规范化碰撞、超长 ID、同 ID 同/异 payload 的正反例；目录/file ID 清单证明无逃逸、误配、误删和最终文件变化。

### AUD-003：ZIP 累计工作量、仓库总量和孤立 temp 容量没有单一可验收上限

- 风险级别：**高**
- 引用：`REQ-010`、不可信输入边界、`CON-001`、`CON-009`、`NON-010/011`；`OUT-003/P03`；`IMP-002/005/009`；`ACC-012/024/029`；方案 §5.1-§5.3、§7、§11-§14（行 161、173、177-179、200、264、275、280、282、323）。代码证据：`ArtifactStoreLedger` 现有常量除 `MaxFileBytes=512 MiB`、4096 child 外，还包含 `MaxSessionBytes=1 GiB` 和 `MaxStoreBytes=8 GiB`；方案只复用单文件/计数值。
- 反例：一个不超过 512 MiB 的压缩包可声明 4096 个各 8 MiB operation 和 4096 个各 8 MiB payload，累计展开/校验工作接近 64 GiB；128 个 512 MiB final package 允许约 64 GiB 压缩存储，尚未计更新 temp。反复制造 `undo_live` temp 删除失败还可在回到 `idle` 后累积未计量残留。方案写“累计 checked-add”但没有给比较上限，同时 §7 允许 idle 后残留，`ACC-029` 又要求稳定态无 temp，判定相互冲突。
- 影响：恶意或畸形 package 可造成可预测的磁盘、CPU 或解压读取拒绝服务；达到容量时的旧包/live/output 零变化无法被统一判定；`ACC-029` 对恢复后残留是 PASS 还是 FAIL 没有唯一答案。
- 最小闭合条件：冻结 package 总展开字节、单次解析/重放累计字节或工作量、仓库 final+temp+reported-residual 总字节/对象数上限及达到上限的确定性错误；说明 1 GiB/8 GiB 既有常量是复用还是有证据地替代；统一“稳定态无 temp”与“删除失败残留”的状态/计量/阻断语义。
- 受影响的通过项：`IMP-002/005/009`、`ACC-012/024/029`，以及恶意 ZIP、有界容量和恢复清理结论。
- 复审证据：边界前/边界值/边界后数据；高压缩比、伪造长度、截断/CRC、重复/大小写别名、路径穿越、未知项、最大 entry/count、残留累积和 final/temp 竞态矩阵；每例记录耗用计量、稳定错误、目录/file ID、live/head/output 前后不变和清理结果。

### AUD-004：提交各阶段的 session close 线性化没有对应验收矩阵

- 风险级别：**高**
- 引用：`REQ-017`、`CON-007/008`、`RACC-019`；`OUT-003/P03`；`IMP-003/008/009`；`ACC-019`；方案 §6、§7、§12（行 183-203、278）。代码证据：当前 `OnSessionClosed` 在持锁状态下直接 `EndLocked`，即使 `OperationBusy` 也会清空 active 并置 idle；P03 必须改变这一已知交错，而不是沿用已有行为。
- 反例：close 分别发生在 guard 后/prewrite 中、temp 已验证后、Dispatcher 排队后但第一项 live 变更前、第一项 live 变更后、live 完成而 package switch 前、package 成功而响应未发出时。方案正文给出了线性化规则，但 `ACC-019` 只写一次泛化的“关闭 session/停止 listener”，没有阶段屏障、每阶段唯一预期、temp 清理、package/head/live、16 名额和新会话可见结果。
- 影响：实现可在某些阶段把已开始 live 的提交误回滚为普通未提交事务，或在 live 前留下 temp，仍可能通过现有 `ACC-019`；因此 `RACC-019` 按当前验收契约不可验收。
- 最小闭合条件：在不新增产品状态的前提下，为上述每个阶段冻结可控屏障/故障点及关闭后的唯一结果；线性化前必须证明 rollback、temp 处理、无 checkpoint；线性化后必须证明有效 package 或唯一 partial；所有情形证明旧会话失效、名额释放、新会话只查询/恢复且不重放。
- 受影响的通过项：需求保真 `RACC-019`；`IMP-003/008/009`、`ACC-019`，以及提交线性化和监听器重启结论。
- 复审证据：x64/x86 每阶段 DELETE、流断开、listener Stop 的确定性 transcript；同步屏障命中证明；live/head/package/temp/file ID、terminal request、session count 和重连状态逐阶段读回。

### AUD-005：Undo/Redo/restore 与 validated migration 的 package-finalize 失败终态未冻结

- 风险级别：**高**
- 引用：`REQ-009`、`REQ-011`、`REQ-024`、`CON-006/009/020/023`；`OUT-003/P03`；`IMP-004/005`；`ACC-011/013/024`；方案 §7、§8.1-§8.2、§13（行 199-201、209、215-223、308-311）。
- 反例：Undo 已把 live 变为 parent 后，保存新 head 的 package replace 失败；或 `validated_drift` apply 已把 live 变为当前工具链结果后，migration child 的 package replace 失败。正文只说“按提交同等的 debug/live/反向恢复门禁”和“不得留下错误 head”，没有选择：自动 forward 恢复旧 live、进入可恢复 partial、还是保留 live 目标但旧 head；也没有说明二次恢复失败、session close、幂等重试时的终态。最后一种会把内部失败伪装成 UI 偏离，前两种则需要不同记录和测试。
- 影响：live 与 package 不能跨域原子的同一问题在 commit 外重新出现；实现者可作出互不兼容选择，`ACC-011/013/024` 均未注入导航/migration finalize 故障，可能留下错误 live/head 或未声明 fallback。
- 最小闭合条件：逐一冻结 Undo、Redo、exact restore、validated migration 在 prewrite/readback/finalize 失败时的 live/head/temp/状态/可用动作；若复用 `PartialCommit`，须扩展其 operation kind、inverse/forward 和跨 session 幂等契约；若保证同步反向恢复，须定义恢复失败进入 `live_state_unknown`。两种路线均不得让 `edit_accept_live` 吞并内部失败。
- 受影响的通过项：`IMP-004/005`、`ACC-011/013/024`，以及三态 migration、分支导航、单一状态和跨域一致性结论。
- 复审证据：store 每阶段故障覆盖 commit、Undo、Redo、exact restore、validated migration；session close 交错；恢复成功/失败与重复请求；每类 P02 22-kind 至少一次 commit→Undo→Redo，删除/attachment/token 反例；最终 live/head/package/temp/输出和状态独立读回。

## 6. 其余语义审核结论

除上述意见外，本轮完整检查未发现以下方向性问题：

- P03 诚实承认 live 与 package 无法跨域原子，并为普通 commit 采用 prewrite→live→atomic switch 与进程级 `committed_without_checkpoint`；进程崩溃窗口未伪装成可恢复。
- 单 package、单 baseline、不可变父链接、payload SHA 去重、未知 format/kind/version 硬停止、三态权限和 migration child 的主方向符合总纲。
- 默认/显式导出避免修改 package，从而不伪装 package+output 双文件事务；使用同目录临时文件、重载/结构/fingerprint/长度/SHA 核验和原子 create/replace，且禁止覆盖源、checkpoint 和 temp。
- 六个 legacy 写工具均被列出，迁移点位于已持有权威 context 的 `StaticToolProvider`；方案明确删除旧 IL snapshot、直接 live rename/save 和第二撤销状态，plain HTTP 不可取得 owner。
- 公开状态保持单一协调器权威，history module 未被赋予第二事务状态；P04-P08 只注册新 operation kind，P09 UI 不被提前实现。
- 双 TFM、x64/x86、P01/P02/static/debug/Python/security 回归和中英文/MCP/完整及定向文档均被列为完成门禁；没有要求人工操作 Win10VM。

这些通过方向仅说明未形成额外阻断意见，不把 `AUD-001..005` 抵消为通过。
