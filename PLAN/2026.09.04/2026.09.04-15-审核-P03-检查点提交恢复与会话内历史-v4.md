## 3. 上一批问题的独立回归结论

v4 已实质关闭上一批 11 的三项问题，未在本记录沿用其编号或结论：

- unknown 明确覆盖 P02 rollback 例外：产品面仅 `edit_status`/`edit_history` 可用；新旧 mutation/export（含 rollback）均稳定返回 `EDIT_LIVE_STATE_UNKNOWN`，且 state/live/head/package/residual 零变化。测试 seam 只能在断言后清理 fixture，不构成产品恢复能力。
- 五类 partial operation 共用恢复模型；Undo 已成功应用 inverse、但 cleanup 失败时，同一 recovery ID 进入 `committing + aborted_temp_cleanup`，仅 `cleanup_temp` 可继续；错向或重复 Undo 不会再次应用 inverse。
- 所有导航先判定 target；仅 exact 可自动切换。validated 必须经 assessment 和显式 confirmed restore 创建 migration child；unverified/unknown 零副作用。begin/commit 同时校验 exact head 与 image/semantic 双指纹。
- 随机源文件族/版本化身份、随机临时 ID 与 file ID 绑定、容量/ZIP、session close/finalize partial、legacy 禁止第二写路径均未因上述修订回退；`RACC-019` 也没有被误写为要求跨会话 terminal 产品 API。

两份 JSON 模型独立机械检查通过：v1 的 15 个 close transition 中 unknown 只有查询、committing 只有查询/cleanup；v2 的 15 个 action 中仅 status/history 为 unknown 可用，cleanup inverse 不重复，导航与 head/双指纹条件符合正文。

## 5. 审计意见

### AUD-001（高）：六个 commit 屏障未进入有效测试 schema，`RACC-019` 无法确定性验收

**风险。** P03 §6 冻结六个屏障：`commit_after_guard_before_temp`、`commit_after_temp_validate`、`commit_dispatcher_queued`、`commit_after_live_first_mutation`、`commit_after_live_complete`、`commit_after_package_switch_before_response`；`ACC-019` 要求 x64/x86 对每个屏障分别执行 DELETE、流断开和 listener Stop。但 P03 §3.2 的新 schema 清单只覆盖 8 个产品工具、两个新非广告测试工具以及五个产品工具扩展，没有扩展既有 `edit_test_barrier`。`edit_test_storage_fault` 只 arm/reset 固定存储阶段故障，不是同步屏障。

**证据。** 当前 `Editing/EditToolProvider.cs:12` 已有 `edit_test_barrier`；`Editing/EditSchemaCatalog.cs` 只加载 P02 嵌入 schema。P02 权威 `PLAN/2026.09.03/P02-contract/contract_source.py:759` 仅允许 `begin_after_copy`、`apply_before_mutation`、`review_before_validation`。当前 coordinator 也只在 `Editing/EditTransactionCoordinator.cs:160,196,235` 命中这三处。工具提供者在调用 coordinator 前按 schema 校验参数，因此仅在实现中增加 `BarrierPoint` 仍不能 arm 新名称。

**反例。** runner 用 `commit_after_live_first_mutation` arm 屏障时先得到非法参数，无法让 close 精确发生在首个 live mutation 后；用调度时序替代时，错误的 linearization、错建 checkpoint 或漏 cleanup 实现也可能偶然通过。

**影响。** `IMP-001/003/008/009`，`ACC-019/024`，`RACC-019`；P03 当前不能独立完成 close/partial 的机械验收。

**最小闭环。** 在 P03 冻结一个 `edit_test_barrier` 的有效声明：保留 P02 三个名称并加入六个名称，明确 arm/snapshot/release/reset、owner、返回字段和实际插点；说明 `EditSchemaCatalog` 如何消费且运行时不产生第二份漂移 schema。它必须保持 `DNMCP_TEST=1` 非广告测试 seam，不得成为产品恢复能力。

**复核证据。** schema 对九个名称全接受、对未知名称拒绝；每个新屏障都有 entered 证据；x64/x86 close 矩阵逐相位读回 state/live/head/package/temp/file ID/recovery/actions，unknown 产品面矩阵在断言前零变化。

### AUD-002（高）：旧 rename 的引用修复语义无法落入已冻结 operation，`RACC-020` 被弱化

**风险。** P03 §10 把 `rename_*` 映射成 begin→structured apply→review→commit，并要求所有 live 变更经 coordinator；`IMP-007/ACC-020` 又要求旧入口保持兼容、可 checkpoint/Undo/Redo/export。但 P02 的 22 个 operation 只修改 TypeDef/MethodDef/FieldDef 的名称、属性或签名，没有表示同模块 TypeRef/MemberRef 修复的 operation。P03 也未冻结 P03 自有的兼容 rename operation、envelope、顺序或 inverse。

**证据。** 当前 `McpTools.Rename.cs:84-95` 对 MethodDef 与所有匹配 MemberRef 原子改名并共同恢复，返回 `updated_member_references`；类型路径同样返回 `updated_type_references`。`CLAUDE.md` 明确 closed generic declaring type 必须同步更新自己的 TypeRef/MemberRef。`tests/fixtures/run-tests.ps1:959-966,1015,1138-1153` 已验证 generic method/field MemberRef、落盘和执行。`Editing/EditOperationRegistry.cs` 中现有 type/method/field 更新没有引用行操作。

**反例。** LegacyAdapter 只下沉 P02 rename 会让调用方 MemberRef 仍指向旧名，保存后执行失败；若 adapter 在 operation registry 外直接修改引用，则 checkpoint replay/Undo 不完整，并重新产生第二条 live 写路径。两种实现都能从当前 P03 文字中被选择。

**影响。** `IMP-002/003/007/009`，`ACC-020`，`RACC-020`；涉及旧 type/method/field rename、checkpoint、Undo/Redo 和 export。

**最小闭环。** 冻结仅服务于现有兼容行为的 normalized rename 语义（或明确可由 registry 承载的 composite）：目标 definition 与所有当前 same-module TypeRef/MemberRef 以固定顺序更新，forward/inverse 序列化旧值及精确行身份，沿同一 coordinator replay/undo/redo，并投影既有引用计数。不得扩为 raw edit 或 P04 能力。

**复核证据。** type/method/field closed-generic fixture 均执行 old call→checkpoint→Undo→Redo→export→reload→execute；读回引用与既有 counters；中途故障时 definition 和引用共同恢复；源码扫描无直接 live 旁路。

### AUD-003（高）：旧 `save_assembly` 的既有回归与新导出安全语义互斥，兼容差异未冻结

**风险。** P03 §9/§10 要求无显式路径时默认写入 ArtifactRoot、不得覆盖 source；旧 `save_assembly` 必须映射 `edit_export` 且不能绕过 history/状态门禁。与此同时 §12 要求现有静态套件继续通过且未声明一项有意的兼容预期变更，也未冻结旧响应字段如何从新响应投影。

**证据。** 当前 `tests/fixtures/run-tests.ps1:317-325` 无 `output_path` 调用 `save_assembly`，要求生成 backup 并使原文件 SHA 改变。当前 `McpTools.IL.cs:597-691` 正是 backup-then-overwrite，并返回 `saved_to`、`bytes_written`、`backup_path`。P03 新 `edit_export` 返回嵌套 `output{path,length,sha256,file_id}`，但旧入口投影未定义。

**反例。** 保持现有测试会违反原文件不变和 ArtifactRoot 默认策略；实现新策略则该必跑回归必然失败，且可把旧 `backup_path` 任意处理。实施者无法同时满足两条冻结要求，结果消费者也没有唯一契约。

**影响。** `IMP-001/005/007/009`，`ACC-014/020`，`RACC-020` 及共同静态回归。

**最小闭环。** 明确这是需求强制的兼容差异，冻结旧响应投影（至少 `saved_to`、`bytes_written`、`backup_path` 与 warning/checkpoint 字段），并定点更新旧回归：无路径时原始 SHA/file identity 不变、无 backup、输出位于 ArtifactRoot；显式路径仍受统一策略。声明这一处预期更新不属于掩盖回归，其他断言全部保留；不得提供覆盖 source 的 fallback。

**复核证据。** 无路径/显式路径双测试、原文件 SHA/file ID 不变、默认输出和旧结果 schema 精确断言、checkpoint/Undo/history 可见；generic rename 等无关旧回归继续通过。
