# S01 私有副本与实时提交技术 Spike 结果

状态：**PASS**
性质：throwaway 技术验证，不是生产实现。

## 验证问题

普通纯托管单模块能否在不替换 dnSpy 实时 `ModuleDef`、不使用 dnSpy 内部 Undo、
不引用 AsmEditor 内部类型的条件下，建立私有副本，并用预生成反向操作形成短临界区提交闭环。

## 实际环境

- 自动化链路：AI → Win10VM MCP → PowerShell/App/FileSystem → 真实 dnSpy。
- dnSpy x64 与 dnSpy-x86 各执行一轮，无人工切换或操作。
- 实时模块访问发生在 WPF Dispatcher，两个架构的 `dispatcher_access` 均为 `true`。
- 测试对象包含方法元数据、IL、异常处理、嵌入式调试信息；代表性事务同时修改方法名、IL 常量和托管资源。

## 结果

- 私有副本写出/重载后的语义指纹与实时模块完全一致。
- MVID 和类型/字段/方法 token 映射保持不变。
- 私有副本编辑期间实时模块指纹不变。
- 三个应用边界分别注入失败，全部逆序恢复到提交前指纹。
- 成功提交后的指纹与执行同样操作的私有副本一致。
- 显式回滚后恢复到提交前指纹。
- 反向操作故意失败时状态可明确进入 `LIVE_STATE_UNKNOWN`；实验随后使用事务外应急清理恢复测试模块，未把应急清理伪装成事务成功。
- 保存并重载回滚后的实时模块，指纹仍与提交前一致。
- 全程保持同一个 dnSpy `ModuleDef` 对象，没有替换文档模块。

## 对正式方案的约束

S01 证明 P02 的基本方向可行，但不代表所有结构化操作已经实现。正式实现仍须：

1. 每个操作类型分别提供预检、正向操作和预生成反向操作。
2. 所有实时访问统一在 WPF Dispatcher 执行。
3. 任一反向操作失败立即进入 `LIVE_STATE_UNKNOWN`，禁止继续编辑和导出。
4. 指纹必须覆盖正式范围内的元数据、IL、资源和符号，不得仅使用 MCP 自有修订号。
