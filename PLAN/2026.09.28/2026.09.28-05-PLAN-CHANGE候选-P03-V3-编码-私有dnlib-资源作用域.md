# PLAN-CHANGE 候选：P03-V3-ENCODING / 私有 dnlib 发行 / 资源作用域声明（T095-C）

> 状态：**候选，未批准**。作者：本轮唯一执行主会话（2026-09-28）。本文件把 R15 `manifest/release-decision.md` 整理为可裁决的正式方案，并补 T095-A 验收发现的应用条件。批准权在用户；批准前不实施任何正式回流。

## 1. 议题与裁决对象

三件事相互独立但建议一并裁决：(1) 新 v3 检查点编码进入正式契约；(2) 私有 dnlib fork 的源码化发行与版本钉住；(3) 资源声明的准确措辞（256 MiB 单 verifier spill 磁盘缓存上限）。

## 2. 新 v3 编码（P03-V3-ENCODING）

**适用范围（核实结果）**：当前候选**不是对所有新谱系启用 v3**。`EditHistoryModule`（私有树）按 baseline 形态逐谱系选择：baseline 含 `System.Object` 引用行 → 沿用 v2（Object 墓碑可去重，无新增行）；不含 → v3。即 v3 只服务于触发已登记结构边界的来源（无 Object 行模块），有 Object 行的模块行为与图像完全保持 v2。

**表示与校验**：
- 墓碑：无 ValueType 引用行时用接口宿主，否则 ValueType 结构宿主；识别绑定已验证模块实例（`RequireVerifiedV3`），禁止仅凭名称前缀判定；事务的 `HistoryFormat` 在 `edit_begin` 由绑定谱系固定，后续引用行变化不改表示。
- 来源行：writer 显式五表 `ReferenceSourceRows` 前缀 + 完整 MethodDef RID 映射；前缀以 `Math.Min(投影, 实际源表行数)` 钳制，投影超源表即抛异常；`isOld` 判定加前缀上界，源外行不得冒充旧行。 RID 映射缺项/含 stale/不连续均抛异常。
- 版本隔离：schema 仅追加 `dnspy.edit.checkpoints.v3` 枚举；未知格式先判 `EDIT_OPERATION_VERSION_UNSUPPORTED` 再走冻结 v1 schema（生产者版本事件与损坏分类不混淆）。v1/v2 读取、导航与墓碑形状**原样保留，不静默迁移**。
- 失败原子性：沿用现有事务/导航/Apply 写出重载门禁；导航图像门禁（计划预校验 + live 图像比对）对 v3 同样生效。

**旧 v2 边界**：v3 正是 P03-OLDV2-NOOBJECT-REVERSE-01 候选的方向 A 载体；若本候选获批，旧包按该候选 §3 的拒绝行为保持，不迁移。

**正式采用条件（来自 T095-A 验收）**：
1. 应用 `extension-HEAD-to-R14-candidate.patch` 时**必须剔除** `tests/edit/p03_vm_acc015.py` 与 `tests/edit/t083_vm_strong_name_deferred.py` 两个 hunk（它们会把 HEAD 正式测试内容回退到分叉前旧版）。
2. 补齐 `build/replay_dnlib.sh` 的还原来源（SDK 自动注入的无后缀 `Microsoft.NETFramework.ReferenceAssemblies` 元包入 source-deps 或显式加只读全局源）。
3. `rebuild_extension.sh`/`make_overlay.py` 重跑会覆盖保留 bin 资产，正式流程改为重定向输出或先备份复核。
4. resource-payload 探针在 Linux 不可复现（WPF 依赖）：其正式回归归入 Windows 主验（T095-D）范围，R15 对应日志保留存疑标注。

## 3. 私有 dnlib 发行（T095-C 第 2 议题）

- 固定官方源 `c78d296c522aae0520df2afd825d48266321cf36`（tarball SHA `c904aa96…`）+ 唯一私有 patch（SHA `28a2f6ba…`，13,109 字节，writer-local 选项不改默认行为）+ 官方 `dnlib.snk`。独立源码重建已由主验收复现（方法集/IL/强名称与包全等）。
- 版本 `4.5.0-r15.private.1`（nupkg SHA `174095c1…`），net48/net10 双 TFM 程序集身份均为 `dnlib, Version=4.5.0.0, PublicKeyToken=50e96378b6e77999`。扩展与 host 一致钉版；不以重打包旧 DLL 冒充源码交付。
- **须用户知悉的身份事实**：fork 沿用官方强名称标识（dnlib 的 snk 本就公开于上游仓库）。同身份意味着：无法与官方 dnlib 4.5.0.0 并存 side-by-side，绑定层视为同一程序集；验收与部署必须以**文件 SHA256**（而非强名称）钉住实际二进制。
- 维护回退：patch 面小（五表前缀 + RID 映射 + csproj 钉版），上游升级时按 patch 重放；若放弃 fork，须同时撤销 v3 编码（两者互为前提）。
- 许可：dnlib MIT，fork 分发合规；发行物标明私有版本与来源 commit。

## 4. 资源作用域声明（T095-C 第 3 议题）

固定措辞：**256 MiB 是单个 verifier 的 spill 磁盘缓存上限**；不是单进程总内存、不是同根跨进程总量、不是仓库谱系包容量，也不新增跨进程锁。R13 证据（两进程聚合 453,113,856 字节）证明该区别真实可观察。若产品需要"同根跨进程总 256 MiB"承诺，须另立资源契约（等待/取消/崩溃/重解析安全设计及实测），不得靠改文案宣称实现。
