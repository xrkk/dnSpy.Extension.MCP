## 5. 根因结论（代码级 + 行为级双重确认）

1. `EditOperationRegistry.ParameterRemove`（`Editing/EditOperationRegistry.cs:349`）对有物理 RID 的尾部 ParamDef 调 `EditDeletedRowsTombstone.AcquireParamHost`；`GetOrCreate`（`Editing/EditDeletedRowsTombstone.cs:67`）以 `module.CorLibTypes.Object.TypeDefOrRef` 为墓碑基类，在无 Object 引用行的模块上新增一行 TypeRef（6→7）。
2. undo（inverse）按 `ReleaseParamHost`→`RemoveIfEmpty` 移除宿主方法与墓碑类型，但该 Object 行在重载后的 live 模块中是**物理源表行**；stock dnlib `PreserveTokensMetadata`（PreserveRids）重新发射全部源表行，图形操作无法使其脱落（与 P03 实施记录 2026.09.04-17 第 526 行结构性结论一致）。
3. `PlanNavigation` 的预校验在"从 baseline 重建的 replay 模块”上进行，多余行在该实例中是图形新增行、可脱落，因此计划校验通过；同一计划作用于重载 live 模块即产生 7 行图像。协调器 `Navigate`（`Editing/EditTransactionCoordinator.cs:1749-1751`）随后以 `EDIT_VALIDATION_FAILED navigation_live_image` 拒绝，不产生静默错像；后续 `Assess` 将 live 归为 drift，需补偿/重放确认。
