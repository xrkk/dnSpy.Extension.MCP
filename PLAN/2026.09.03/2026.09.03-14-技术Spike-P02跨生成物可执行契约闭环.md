## 1. 操作合法域

单一源加入 `p02-typesig-v1` EBNF、18 个 CLI primitive、泛型变量/构造泛型/嵌套/数组/pointer/byref 规则、唯一解析规则、有效/无效向量，以及 `modreq/modopt/fnptr/sentinel` 的固定能力拒绝。

使用本机实际依赖 `/home/adminn/.nuget/packages/dnlib/4.5.0/lib/net6.0/dnlib.dll` 运行只读反射最小实验，得到八个 enum 的已定义位并冻结为 mask/default：Type `16219583/0`、Method `65535/128`、MethodImpl `6143/0`、Field `47095/0`、Property `5632/0`、Event `1536/0`、Param `12319/0`、GenericParam `63/0`。schema 使用标准范围和 `x-dnspy-defined-bit-mask`；实施时必须执行 `(value & ~mask)==0`。

常量补充单 Unicode scalar char pattern、r4/r8 有限范围和 null/clear 规则；property/event add 禁止显式 null，update 的 nullable 字段继续表示清除；opcode 必须按 dnlib 4.5.0 `OpCodes` 表取得 OperandType 后匹配 18-kind union。

## 2. 指纹 component-specific recipe

61 个 component 各自产生唯一 recipe，包含 category、fixture 前置、component-specific target、mutate action、真实 reorder action、component-specific canonical readback 和 restore action。122 个 case 不再只是标签/布尔值。

`edit_test_external_mutation` 仅接受 corpus `case_id`，返回 recipe/target/action、前后 readback、前后/恢复指纹和 restore evidence；runner 必须按生成 recipe 对拍，不能用同一 TypeDef mutation 或 reorder no-op 代替其他 component。

## 3. review 容量和生命周期

单一源与独立 validator 各自实现递归 schema 最大 JSON UTF-8 上界计算：所有可选字段均出现；每个 JSON Schema code point 按最坏 12 字节 surrogate escape 计算；数组使用 maxItems，object 计入全部键和分隔符。

- 独立计算最大合法 `edit_review` 响应：`14,687,498` bytes
- 独立 full review slot：`16,777,216` bytes
- 机械余量：`2,089,718` bytes
- 旧 2 MiB 反例由 mutation test 明确拒绝

连续 review 的 first/new/old/apply-success 四条生命周期现已写入 `capacity-golden.json`，不再只存在于 Python 内存对象。

## 4. fault/evidence 与动态五态

240 条 fault row 全部具有相同九字段 projection：`fault_id,operation_index,step_index,operation_kind,direction,boundary,primitive_kind,target,step`。公开 evidence 的 manifest/oracle/actual/covered 四个集合使用完全相同的 row schema；golden 与 lowering 独立逐行推导和互验。

动态 validation 从五个宽松 branch 改为七个严格 branch：not_requested、not_applicable、blocked、passed 和 failed 的 pre-artifact/cleaned/residual 三分支。前三态 events 必须空，passed 必须有事件并完成 terminate/delete，所有返回均要求 debug idle；failed 明确 phase、artifact 和清理/残留组合。

## 5. validator 独立性和失败能力

`validate_contract.py` 不 import 规范源，默认先读取已有生成物，再将 generator 输出写入临时目录逐字节比较，因此不会先覆盖待验对象。它独立解析 TypeSig、计算 schema 上界、从 lowering 推导 fault rows、交叉验证 evidence/corpus/capacity/dynamic，并按 `requirements-map.json` 和独立固定映射逐 RACC 计算保真。

实际命令：

`python3 PLAN/2026.09.03/P02-contract/validate_contract.py`

结果：112/112 checks，errors=0，六个 RACC 全部 true，保真 `6/6/0/0/0`，PASS。

失败能力命令：

`python3 PLAN/2026.09.03/P02-contract/test_validator_mutations.py`

结果：5/5 PASS。旧 2 MiB slot、fault 缺 target、无关 component mutation、两字符 char、缺 RACC 五种变异均令 validator 退出 1，并命中各自语义错误而不只是哈希错误。
