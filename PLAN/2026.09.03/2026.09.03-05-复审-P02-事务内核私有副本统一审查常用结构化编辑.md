## 4. 未闭合与新增审计意见

### AUD-001：公开 schema 与逐操作语义仍未真正冻结

- 首次提出轮次：第 1 轮；本轮结论：未闭合；严重度：高。
- 来源与复审证据：REQ-002、CON-024、NON-001；OUT-002；v1 §4.1 第 138-150 行、§4.2 第 152-156 行、§4.3 第 158-187 行、ACC-003。§4.1 承诺完整 inline schema，但正文只列 properties 名称和 success 摘要，没有实际 output 分支 required/互斥，也没有全部嵌套字段类型、范围和枚举。
- 具体反例 1：`method_add` 的 signature 已包含 `parameter_types=[System.String]`，并声明这些参数没有 ParamDef、需 `parameter_add` 命名；但 `parameter_add` 又把 `parameter_type` 列为可选，并规定向 `MethodSig.Params` 插入新槽。实现 A 用它只给现有第 0 槽建 ParamDef，得到 `M(string)`；实现 B 按字面插入，得到 `M(string,string)`；不提供 optional type 时实现 B 又没有可插入的类型。两者都能引用本文。
- 具体反例 2：`event_add` 把 add/remove refs 列为 optional，却说二者必须同时存在；`event_update.raise_ref` 未标 nullable，无法判断省略、清除和保持；field constant 没有冻结 JSON 数字范围、char、NaN/Infinity 或 byte 表示。严格宿主能校验“一个实现的 schema”，却无法判断该 schema 是否符合唯一方案。
- 风险/影响：22-kind golden、Python client、规范 diff、P03 操作持久化和跨版本重放没有唯一契约。影响 RACC-003、ACC-003、IMP-003/004/005 及 AUD-006 的测试 oracle。
- 最小闭合条件：在方案中给出五工具及 22 branch 的完整可展开 JSON Schema 或等价逐字段规范；拆分“给现有签名槽创建 ParamDef”和“插入签名参数”，或明确 parameter_add 的唯一一种语义；冻结 event accessor 的 required/null/clear 规则、constant 的 JSON 编码与范围、所有成功/错误 output 分支的 required/互斥。
- 复审证据：schema fixture 经严格 validator；method_add(parameter)→命名而不改变签名的读回；参数插入/删除独立案例；event 三 accessor 清除案例；全部常量边界和逐字节响应 golden。

### AUD-004：主要线性化协议已补，锁外等待和取消结果仍未闭合

### AUD-005：容量上限互相冲突，过大模块与 UI 短占用仍不可验

- 首次提出轮次：第 1 轮；本轮结论：未闭合；严重度：由中提升为高。
- 来源与复审证据：CON-005、NON-018；v1 §3.1 第 83 行、§3.3a 第 104-112 行、§3.4 第 128-132 行、ACC-009 第 257 行、§8 第 276-277 行。
- 具体反例 1：每会话 cache 最多 256 项且不逐出；begin、apply、review、rollback 都需要 request ID。`begin + 255 apply` 已占满 256 项，随后 review 和 rollback 都会 `EDIT_CAPACITY_EXCEEDED`；声明的 256 successful operations 更必然不可到达。owner 还能用 status 刷新活动时间，恢复建议“rollback 或缩小事务”中的 rollback 本身不可用。8 MiB response 上限可更早产生同类锁死。
- 具体反例 2：没有源模块的总字节、metadata row、resource/PDB 或预计 fingerprint 成本上限。begin 被要求在 WPF Dispatcher 定位并完成完整写出/重载；test apply 又在 Dispatcher 内计算最终全模块指纹。一个巨大但可序列化模块即使只改标量也可长时间冻结 UI。记录 wall-clock 而没有上限和通过阈值不能证明“短”。集合插入/移除也不天然是常量时间。
- 风险/影响：事务无法 review/rollback，只能等 close/timeout；UI 可长时间无响应；无法靠前置能力门禁避免 OOM/长暂停。影响 RACC-001/002/009、ACC-001/002/009、IMP-001/002/004/006、资源和 P03 交接。
- 最小闭合条件：为 review/rollback/close 清理预留或豁免 cache 容量；定义满容量拒绝本身的幂等落点和事务结束后的安全回收。使“256 operations”与 cache/response 预算同时可达。增加模块成本准入（字节、行数、资源/PDB、估算步骤/时间），以及双架构可执行的 Dispatcher 最大占用阈值；超限必须在实时副作用前确定拒绝。
- 复审证据：最大事务完成 review 和 rollback；cache 项/字节满载时 rollback、close、timeout 均可恢复；256/257 边界真实可达；模块准入边界/超一；x86/x64 最大允许模块和 plan 的 Dispatcher 时间满足固定阈值，无步骤间外部 mutation 窗口。

### AUD-006：验收矩阵仍有动态输出缺口与 fault 循环自证

- 首次提出轮次：第 1 轮；本轮结论：未闭合；严重度：高。
- 来源与复审证据：RACC-003/009/010、CON-005/020/021/024；v1 §4.1 第 142-150 行、§5 第 206-216 行、§7 第 240-267 行。
- 具体反例 1：正文把 dynamic 结果称为 `passed|failed|blocked|not_applicable`，但 failed/blocked 同时被定义为领域错误且不生成 review；§4.1 只在 success result 列 dynamic validation，错误信封没有 `validation_attempt`、事件、清理或残留路径字段。严格 output schema 的客户端无法按 ACC-010 唯一观察“四态与真实事件一致”。
- 具体反例 2：manifest 与覆盖集都由同一个实现生成。若 `property_add` 的实现把 property 集合插入和 MethodSemantics 链接藏在一个自称 primitive step 中，manifest 只有一个 ID，注入集合也只有一个 ID，等式仍全绿，却没有验证链接 mutation 后失败的反向恢复。当前没有独立 operation→primitive lowering 表或实际 mutation trace oracle。
- 风险/影响：动态失败证据会落在 schema 外；遗漏实时 mutation 边界仍可产生全绿 fault summary。影响 RACC-009/010、ACC-009/010、IMP-003/005/006/008/009 和严格宿主兼容。
- 最小闭合条件：冻结 success/error 中统一的 `dynamic_validation` 或 `validation_attempt` schema，包括 state、真实事件、路径身份、cleanup/debug-idle 结果；明确 review 是否存在。为每个 22 kind 冻结规范 primitive lowering 下界/顺序，或用独立 mutation trace 比较 manifest，故障点精确定义为 mutation 前/后边界。
- 复审证据：四态和 not_requested 全部通过各自 output schema；启动/终止/删除失败仍有结构化证据；逐 kind 的实际 mutation trace 与 manifest 集合相等，property/event/generic 多边 mutation 均可单独注入并验证反向恢复。

### AUD-008：RACC-002 的端口变化生命周期路径没有验收落点

- 首次提出轮次：第 2 轮（第 1 次全面复审）；严重度：中。
- 来源与复审证据：REQ-017、CON-007、RACC-002；总纲 ACC-002；v1 §3.2、§7 ACC-002 第 255、264 行。上游要求地址或端口变化时不猜测新地址、不自动重放不确定修改请求；v1 的实际动作和预期只覆盖 listener Apply restart 及“stdio 同 URL 重连”。
- 具体反例：Apply 把 15378 改为 15379，client 若扫描 `Port..Port+19` 或沿用旧 pending request 到新 endpoint 后 replay，事务可能重复；runner 只执行 same-URL case 仍可全绿。
- 风险/影响：RACC-002 被语义缩窄，不能证明配置变更时的未提交回滚和禁止不确定 replay。影响 ACC-002、IMP-007/008、Python client 和会话生命周期交接。
- 最小闭合条件：在 ACC-002 增加 host/port 改变案例；冻结旧 client 停止、旧 session/transaction/cache 失效、不得端口扫描/猜测/自动重放，只有用户更新配置后显式初始化新 URL 才可继续。
- 复审证据：旧/新 URL、session ID、transaction/cache 状态、client 日志和请求 transcript，证明没有对新 endpoint 发送旧变更 request ID/payload。
