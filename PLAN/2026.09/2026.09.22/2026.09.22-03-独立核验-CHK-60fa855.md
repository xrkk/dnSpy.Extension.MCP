## 4. CHK 发现（编号仅属于本记录，不是 AUD）

### CHK-20260922-03-01：暂停路径线程句柄判空反转（高）

位置：`Debugger/DebugSessionService.cs:3576`，mint 解引用位置 `:2050–2059`；始于 `ed6cacc`。

最终表达式为 `eventThread is not null ? null : MintThreadHandle(eventThread, eventPauseEpoch)`。有真实线程时返回 null；无线程时反而把 null 送入解引用。隔离表达式复现分别得到 `present_thread_projection=null`、`absent_thread_exception=NullReferenceException`。生产的 breakpoint/step 明细随后可能投影为 `unknown-thread`，异常明细失去线程关联；无线程分支可能中断暂停采集。

这是通用暂停链上的确定实现回归，不是强名称夹具专属问题。影响 RACC-028.C1.O1、C1.O4。43 个编辑 harness 探针没有执行这段真实采集逻辑，不能抵消反例。

### CHK-20260922-03-02：强名称来源与身份判据弱于已批准规范（高）

位置：`Debugger/DebugSessionService.cs:3602–3665`；依据：`2026.09.22-02`“四条同时成立”和强名称 AssemblyRef 身份 `name+version+publicKeyToken`。

- 五参生产分类器在 `moduleName=mscorlib` 时完全跳过 host 引用及加载差集；探针使用 `hostTargetPath=null`、`loadedModuleNames=null` 仍放行。
- 非 loader 模块也能走差分支路。探针创建仅含未加载强引用的 Host 元数据，传入样本模块名 `Host`、人工构造的 HRESULT/身份消息，即获得观测。这些输入没有真实 loader 失败来源；“引用存在且尚未加载”不能自行证明失败发生。
- `HostReferencesStrongIdentity` 只比较 name/token，不比较 version。探针 host 引用版本 `1.0.0.0`，消息版本 `9.9.9.9`，仍被分类接受。编辑门随后拿消息中的版本比目标，不能补回“host 实际引用的失败身份”这一缺失约束。
- 提交/终态文件把日志整数 `-2146233318` 解释为 `0x8013DE1A`，实际为 **`0x8013141A`**；`0x8013DE1A` 的有符号整数为 `-2146181606`。双常量扩展的所述观测依据不成立，批准记录还明确要求扩展集合须重审。

白盒 `StrongNameEvidenceProbe.cs` 调用三参重载，其 sample-module 拒绝不覆盖生产五参支路。这里确认的是生产分类算法反例和规范偏离，未把它冒称已完成 VM 自抛攻击端到端。影响 RACC-016.C2.O1、C2.O2；材料未提供对这次放宽的独立批准记录。即使以后批准新的信任模型，也须重新证明可信因果，不能仅更新文案消除上述反例。
