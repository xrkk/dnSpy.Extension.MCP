# PLAN-CHANGE — 强名称可信 loader provenance 与 failed-binding target 证据适配

- 登记：2026-09-22 06:1x CST。裁决：用户于 2026-09-22 批准"批准并本轮实施"（会话内 AskUserQuestion 记录）。
- 影响规范：P08（`PLAN/2026.09.14/2026.09.14-17-实施子方案-P08-资源大载荷与强名称兼容.md`）ACC-016/RACC-016 的证据适配子层；不改 ACC-016 的行为义务本身（默认保留身份、仅动态失败后建分支、入站影响报告、能力边界诚实——全部维持）。
- 背景：T026/T027 查明 dnSpy 6.6.0 公开异常契约（type/message/HResult/chance/unhandled/thread/module）无法区分 CLR loader 强名称验证失败与样本自抛异常（无 loader 来源、无失败绑定目标身份），R2 以 fail-closed 恒拒绝收口并登记本候选。

## 变更内容：结构可信证据流（新信任模型）

`strong_name_remove` 的 `dynamic_failure` 证据从"异常形态推断"改为**结构判据组合**，四条子判据全部来自样本代码不可伪造的调试器事实：

1. **loader 域来源**：异常的 ICorDebug 模块映射归属为框架 loader 模块（`mscorlib` / `System.Private.CoreLib`）。样本代码抛出的异常其 Module 归属为样本模块自身或其依赖（已在模块加载清单中），不可能归属框架 loader 模块——T027 两个红态反例（自抛/依赖抛）均被此条判别。
2. **强名称失败 HRESULT**：`HResult == 0x8013141A`（Strong Name signature invalid 的 FileLoadException）。集合常量起步为该单值，扩展需重审。
3. **引用差集（failed-binding target 身份）**：调试会话启动目标（host）元数据中的**强名称 AssemblyRef 闭包**（name+version+publicKeyToken，来自 host 模块元数据，样本不可伪造）减去**已观察加载模块集**（ICorDebug 模块事件）——非空即给出"被引用但从未加载"的候选身份。
4. **消息互证（非独立依据）**：loader 异常 message 须点名候选之一（名称出现）；判据 1–3 已独立成立，本条仅消解多候选歧义，无名命中即 fail-closed 拒绝。

四条同时成立 → 记录一次 `StrongNameFailureObservation`：`{session_id, generation, event_cursor, loader_module, hresult, failed_target{name, version, public_key_token}, target_ref_source}`，写入调试事件缓冲对应 cursor。

## 门控与消费

- `EditTransactionCoordinator.ValidateStrongNameEvidence` 由恒拒绝改为：既有结构校验（公钥在场/证据形/session_id/cursor>0/kind=exception）＋按 `session_id+event_cursor` 读取观测（须存在、未消费、未过期）＋**身份绑定**（`failed_target` 的 name+version+publicKeyToken 必须与被编辑目标模块自身 Assembly 身份逐字段相等——运行时被拒的正是要去除强名称的那个程序集）。
- **一次消费**：观测读取成功即标记 consumed；同 cursor 复用、跨目标复用、过期 cursor 一律拒绝。
- 旧反例矩阵全部维持拒绝：自抛同 HRESULT（模块归属≠loader）、依赖抛错（同前）、跨 session、无效 cursor、正常退出、无签名目标。
- `EditOperationRegistry.StrongNameRemove` 操作体不变（移除公钥+风险行+可逆）。

## 验证义务

1. 白盒（DNMCP_TEST 注入 seam）：正例晋升（合成观测→门过→strong_name_remove 生效→commit→导出重载为无强名称）、T027 反例仍拒、一次消费、跨 session、cursor 过期、身份不匹配（version/pkt 漂移）。
2. 端到端（需另行授权）：VM 关闭强名称绕过（`HKLM\SOFTWARE\Microsoft\.NETFramework AllowStrongNameBypass=0`，系统级授权另申请）→ host 引用被篡改强名称目标 → 真实 loader 失败 → 观测 → 门过 → 授权移除 → 导出/动态验证。端到端未获批时 ACC-016 成功分支保持"实现完成+白盒闭合+端到端 BLOCKED（授权）"的如实分层。
3. 既有 debug/编辑回归不回归（负例矩阵、静态 E2E 双架构、ACC-020/025/029 等）。
