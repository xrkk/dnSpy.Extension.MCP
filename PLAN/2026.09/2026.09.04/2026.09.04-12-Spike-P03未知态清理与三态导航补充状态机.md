## 1. 待验证问题

在不新增产品恢复 API、状态、数据库、跨会话 terminal 索引或逐检查点完整程序集的前提下，验证以下三个问题能否形成唯一实施契约：

1. `live_state_unknown` 是否可以明确覆盖 P02 的旧 rollback 例外，使产品面只保留查询并由重启 dnSpy 退出；
2. partial `undo_live` 已恢复 live、但绑定 temp 删除失败时，是否可以只保留一个状态、recovery kind 和后续动作；
3. migration child 与 Undo/Redo/restore/begin/commit 的组合，是否可以保证三态确认不能被普通导航绕过，同时让 head/live 不变量可机械验收。

对应需求和约束为 `REQ-009/011/022/024`、`CON-006/010/011/020/023`、`RACC-011/013/024`；对应审计意见为 `AUD-001..003`。

## 2. 已核实事实

- P02 当前在 unknown 下放行 `edit_rollback`，但该动作只释放私有事务并把 top-level state 设为 idle，不能证明或恢复未知 live；真正紧急恢复只存在于 `DNMCP_TEST` seam。因此继续继承该例外会违反 `CON-020`，P03 必须明确安全纠正。
- 前一个 Spike 的 T11 已选择 `committing + aborted_temp_cleanup + cleanup_temp`；P03 v3 §5.3 的 `committed_without_checkpoint + undo_live` 是未清除的矛盾旧文，而不是另一项需求。
- `validated_drift` 的明确确认和 migration child 来自 `CON-023`。Undo/Redo 输入没有 replay ID 或确认字段，因此不能自动导航到 validated 目标。历史导航在动作前已有完整 replay 规划阶段，可复用三态评估而无需新接口。

## 3. 最小模型和冻结决定

模型列出 15 个 unknown 产品动作、3 个 cleanup 转换和 8 个导航转换，并冻结：

1. unknown 下公开只允许 `edit_status` 与 `edit_history`。`edit_rollback` 与所有其他产品 mutation/export 均返回 `EDIT_LIVE_STATE_UNKNOWN`，live/state/head/package/residual 不变；P03 对既有五工具的兼容明确不包含该安全纠正。只由 dnSpy 进程重启并重新加载源退出 unknown；`DNMCP_TEST` 清场不是产品转换。
2. inverse 已验证恢复 pre-live 后若 temp 删除失败，唯一投影是 `state=committing`、`recovery.kind=aborted_temp_cleanup`、允许 `edit_status/edit_history/cleanup_temp`；原 recovery ID 继续绑定该 cleanup 事实，重复错误动作不得再执行 inverse。
3. Undo/Redo/restore 在任何 live/head/package 写入前评估目标。只有当前工具链 `exact` 的目标可以直接导航；`validated_drift` 的自动 Undo/Redo 返回 `EDIT_REPLAY_CONFIRMATION_REQUIRED` 且零副作用，调用者必须 `edit_restore(assess)` 后以有效 replay ID 和确认执行 apply，由目标为 parent 创建记录当前 exact image 的零语义 migration child；`unverified_drift` 和未知格式/种类/版本硬拒绝且零副作用。
4. 每次成功直接导航后，选定 head 必须在当前工具链下为 exact，live image/semantic fingerprint 必须等于该 replay 结果。begin/commit 也要求 exact head 与 live 的 image/semantic fingerprint 同时匹配。这样从 migration child Undo 到 validated parent 会拒绝，不会把 head 移到非 exact 节点；显式恢复会在 parent 下创建新的 migration child并保留原分支。

## 4. 机械验证

在仓库根对模型执行 `jq -e` 聚合断言，验证：

- 15 个 unknown 动作中只有两个 query 为 allowed，其余 mutation/export 全部返回 `EDIT_LIVE_STATE_UNKNOWN` 并保持 unknown；
- 所有 `committing` cleanup 转换都只有 `aborted_temp_cleanup` 和 `cleanup_temp`，且 inverse 不可重复；
- 所有直接 navigation 成功目标均为 exact；所有 drift/unknown 拒绝均不改变 head/live/checkpoint；
- 唯一创建 migration checkpoint 的转换是 confirmed restore apply；
- 七个全局不变量全部为 true。

## 5. 判定与方案输入

Spike 通过。三个问题不需要用户重新裁决，也不需要扩大 P03：

- `AUD-001` 通过明确废止 unknown 下的产品 rollback 例外闭合；
- `AUD-002` 通过全文统一为 `committing + aborted_temp_cleanup + cleanup_temp` 闭合；
