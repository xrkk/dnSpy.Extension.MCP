- 修改位置：方案 v1 §4.2、§4.3、§4.4、§8.3、IMP-002/006、ACC-012/025。
- 实际修改：`edit_begin` 增加可选 `source_family_id`；`edit_accept_live` 强制绑定 `source_family_id` 与 `superseded_lineage_id`；新增 `EDIT_SOURCE_IDENTITY_CONFLICT`；冻结随机 family ID、versioned `source_identity.v1`、P02 SHA-256 与 handle-derived final path hash 算法、进程内绑定优先级、MVID+semantic/file-identity 候选、显式 family 筛选、active-leaf 唯一性、Save As、同路径替换、相同副本、多 loaded module、pathless、跨进程及无候选新 family 规则；响应只暴露不含原始路径的摘要。
- 最小闭合条件：已满足。身份输入、格式/哈希版本、候选/拒绝规则、可观察摘要和全部反例均已进入规范正文及 ACC-012/025。
- 影响：改变 IMP-002/006 及 ACC-012/025；恢复 `RACC-025` 的完整可验收语义。

### AUD-002：同意

- 判断：P02 `request_id` 是不可信的一般字符串，不能直接或经有碰撞清洗后成为 Windows 路径组件。
- 修改位置：方案 v1 §5.1、§6、§7、IMP-002/003/005、ACC-024/029。
- 实际修改：临时对象改用服务端独立随机 `tmp-[0-9a-f]{32}`；请求终态/PartialCommit 保存 temp ID、path、file ID、length 和 SHA；同请求重试从终态恢复原 temp 身份，不重新生成；任何请求原文/清洗值/截断值均不得进入路径；创建、完成和删除均以请求持有句柄与 file ID 校验。
- 最小闭合条件：已满足。安全映射、长度、重试定位、所有权、同目录/非重解析验证和错误边界均已冻结。
- 影响：改变 package prewrite/recovery 的内部身份，不改变公开 request-id 幂等契约。

### AUD-003：同意

- 判断：v0 只列单文件和数量限制，不能约束 ZIP 总展开工作、仓库 final/temp/residual 总量，也与 cleanup 失败后的 idle 语义冲突。
- 修改位置：方案 v1 §5.2、§5.3、§7、IMP-002/005/009、ACC-024/029。
- 实际修改：历史模块在 debug 未启用时也独立取得安全目录租约；复用 `MaxFileBytes=512 MiB`、`MaxSessionBytes=1 GiB`、`MaxStoreBytes=8 GiB`、`MaxStoreChildren=4096`；统一计量 final、temp、孤立/清理残留和未知直接子对象；限定 128 个有效 lineage、4096 个物理 ZIP entry、1 GiB 声明展开/单次读取、各类 entry 上限及 checked-add operation 上限；非法或不可计量对象使写入 fail-closed；cleanup 失败保持原 recovery 和 partial，不回 idle、不重复 inverse；进程崩溃残留只读报告并计量，永不自动采信。
- 最小闭合条件：已满足。容量常量来源、边界错误、残留语义和 ACC-029 边界/恶意矩阵均唯一。
- 影响：改变存储资源门禁、恢复完成条件及 ACC-024/029；不引入后台清理或崩溃恢复。

### AUD-004：同意

- 判断：v0 虽声明 Dispatcher 第一项 live 变更为线性化点，但 ACC-019 没有逐阶段证明 session close 的唯一结果。
- 修改位置：方案 v1 §6、§12 ACC-019、IMP-003/008/009。
- 实际修改：冻结六个可控屏障：`commit_after_guard_before_temp`、`commit_after_temp_validate`、`commit_dispatcher_queued`、`commit_after_live_first_mutation`、`commit_after_live_complete`、`commit_after_package_switch_before_response`；前三阶段关闭必须 rollback、清 temp、live/head/package 不变；后三阶段必须得到唯一 checkpoint，或在同时注入 finalize 故障时得到唯一 PartialCommit。ACC-019 要求 x86/x64 分别对每一屏障执行 DELETE、流断开和 listener Stop，并读回 session count、terminal request、live/head/package/temp/file ID。
- 最小闭合条件：已满足。屏障、每阶段唯一结果、名额释放、重连只查询/恢复和不重放均可观测。
- 影响：改变 commit/session lifecycle 的并发验收契约；恢复 `RACC-019` 的完整可验收性。

### AUD-005：同意

- 判断：navigation/migration 的 live 与 package 跨域窗口必须与 commit 一样有明确终态，不能退化成 UI 偏离。
- 修改位置：方案 v1 §7、§8.1、IMP-003/004/005、ACC-011/013/024。
- 实际修改：把进程级 PartialCommit 扩展为 `operation_kind=commit|undo|redo|restore|migration`；导航先完整 prewrite/readback，再修改 live，最后切包；prewrite/readback 失败零副作用；live 失败 inverse 成功回 pre-head，失败进入 `live_state_unknown`；finalize 失败进入同一 partial；`retry_checkpoint` 只采用 post-head，`undo_live` 只恢复 pre-action live/head；session close 和幂等重试沿用同一线性化规则；`edit_accept_live` 不得吞并内部失败。ACC-024 对五种 operation kind 逐阶段注入并读回最终状态。
- 最小闭合条件：已满足。五类操作的失败阶段、live/head/temp、可用恢复动作、二次失败和跨会话幂等均有唯一答案。
- 影响：改变核心 navigation/recovery 状态机和 ACC-011/013/024；不增加第二状态机。
