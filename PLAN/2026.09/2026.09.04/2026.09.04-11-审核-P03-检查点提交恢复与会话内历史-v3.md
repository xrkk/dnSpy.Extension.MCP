### AUD-003：零操作 migration child 与 Undo/Redo/head 的三态组合未冻结

- 风险：**高**；这是本批次新发现的独立历史/三态契约缺口。
- 证据：P03 v3 §8.2 规定旧 checkpoint 在当前工具链重放为 `validated_drift` 时，经确认以目标 checkpoint 为 parent 创建“零语义操作”的 migration child，并记录当前工具链 image SHA。§8.1 又无例外地规定 Undo 把 head 移到 parent、按 child inverse 导航；§4.2 的 `edit_undo/edit_redo` 没有 replay ID 或 drift confirmation 输入。§4.3/§8.3 要求 begin 比较 live 与 active head，但一处使用“head 指纹”，resolver 又使用 semantic fingerprint，未规定 migration Undo 后 head 的 image/semantic/classification 不变量。`ACC-011` 只测普通 commit 分支；`ACC-013` 只测 assess/apply 生成 migration，未组合 migration→Undo→Redo→begin/commit/export。
- 反例：旧点 C 的记录 image 为 A、semantic 为 S；当前工具链重放得到 image B、semantic 仍为 S，于是确认后创建空操作 migration M（parent=C，记录 B）。Undo M 时 inverse 为空，live 仍为 B，但 head 变为 C。若 head 要求记录 image A，则 live/head 立刻冲突且 Undo 不能完成；若只比较 semantic S，则 C 仍是 `validated_drift`，随后 begin/普通 commit 可能绕过“validated 必须明确确认并形成 migration child”；若实现直接拒绝该 Undo，当前接口、错误和 ACC 又没有冻结这一例外。Redo 和跨再次升级工具链时同样有多种不兼容结果。
- 影响：三态权限可能被 head 移动绕过，或 migration checkpoint 形成不可正常导航的分支；实现者无法唯一决定 Undo/Redo 是否改变 head、何时要求确认、begin 以 image 还是 semantic 为准。影响 `IMP-004/006/009`、`ACC-011/012/013` 和需求保真 `RACC-013`。
- 最小闭合条件：冻结“current head 与 live”的 image/semantic/replay-classification 不变量；明确从/向 migration child 的 Undo/Redo 在 exact、validated、unverified 下分别允许、拒绝或要求哪种已冻结确认，且不得通过普通 begin/commit 绕过 `CON-023`。如果不扩 Undo/Redo 输入，须给出稳定错误和可执行替代流程；如果允许导航，须说明零操作 child 如何保持 head/live 一致。不得引入完整程序集逐 checkpoint 副本来规避。
- 受影响通过项：P03 §4.2/4.3/8.1/8.2、`IMP-004/006/009`、`ACC-011/012/013`、需求保真 `RACC-013`。
- 复审证据：两个真实 producer/tool 版本下执行 C(validated)→确认生成 M→Undo→status/history→begin/commit/export→Redo→再次升级工具版本；逐步记录 recorded/current image SHA、semantic fingerprint、classification、head、replay ID、确认事实和零副作用拒绝，证明不会静默降级、绕确认或形成不可达 head。
