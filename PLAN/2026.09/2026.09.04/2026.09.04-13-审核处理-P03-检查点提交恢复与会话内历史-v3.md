## 2. 逐条处理

### AUD-001 — 同意，高风险

- 证据：P02 当前 unknown 守卫放行产品 `edit_rollback`，而 rollback 只释放事务并设 idle；它没有 live inverse 或指纹验证。该行为与 `CON-020` 和 P03 query-only 决定冲突。
- 修改：v4 §4.1、§4.3、§6、§7、IMP-001、IMP-009、ACC-019/024 明确废止 unknown 下 rollback 例外。unknown 公开只允许 `edit_status/edit_history`；包括 rollback 在内的全部新旧 mutation/export 返回 `EDIT_LIVE_STATE_UNKNOWN`，且 live/state/head/package/residual 不变。
- 边界：普通事务态的 P02 rollback 输入、字段和语义继续兼容；安全纠正只作用于 unknown。`DNMCP_TEST` emergency cleanup 仅在阻断证据保存后清理 fixture，不进入产品 schema、响应能力或成功条件。
- 最小闭合条件：已由 Spike 15 个产品动作矩阵和 v4 ACC-019/024 逐一动作 oracle 固化。

### AUD-002 — 同意，高风险

- 证据：v3 §5.3 的旧文字与 §4.2/§7、前一 Spike T11 冲突，允许同一事件出现 `committed_without_checkpoint+undo_live` 或 `committing+cleanup_temp` 两种实现。
- 修改：v4 §5.3、§7、IMP-003/005/009、ACC-019/024/029 全文只保留一个转换：partial `undo_live` inverse 成功后 cleanup 失败，同 recovery ID 原子转为 `committing + aborted_temp_cleanup`，allowed action 只剩 `cleanup_temp`；错误或重复 `undo_live` 不得再次执行 inverse。
- 边界：cleanup 仍只删除 path/file-ID/length/SHA 精确绑定的 temp；失败保持同 recovery 事实，不回 idle，不新增第二状态。
- 最小闭合条件：已由 Spike C01..C03 和 v4 五类 partial 的 ACC-024 矩阵固化。

### AUD-003 — 同意，高风险

- 证据：v3 没有说明 migration child 的 validated parent 能否被没有 replay/确认输入的 Undo 自动选为 head，确实可能绕过 `CON-023` 或形成 live/head 不一致。
- 修改：v4 §4.2、§4.3、§8.1..8.3、IMP-004/006/009、ACC-011/013 固定统一规则。任何自动导航先评估 target；只有 exact 目标可导航。validated 目标返回 `EDIT_REPLAY_CONFIRMATION_REQUIRED` 且零副作用，必须 assess 后 confirmed restore，并在目标下创建新的 exact migration child；unverified/未知版本硬拒绝。每次成功导航后 head 必须在当前工具链 exact，live image/semantic 双指纹必须等于 replay；begin/commit 也要求该不变量。
- 边界：不增加 Undo/Redo 输入、不复制完整程序集、不删除旧 migration 分支；validated migration 仍是总纲允许的既有 fallback。
- 最小闭合条件：已由 Spike N01..N08 及 v4 ACC-011/013 的跨版本组合矩阵固化。
