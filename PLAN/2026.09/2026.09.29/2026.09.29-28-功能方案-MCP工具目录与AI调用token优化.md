## 1. 背景与问题

AI 经 MCP 使用本扩展时的两类成本:

1. **固定成本**: 每会话 `tools/list` 载荷 174.6KB 全量注入（约 4~6 万 token 量级）, 其中 `edit_apply` 单工具 schema 占 59.7%（39 个操作分支的 oneOf 全量内联）——来源 `Editing/Contracts/p03-tool-schemas.json`（嵌入资源 `dnspy.edit.p03-tool-schemas.json`, 经 `Editing/EditSchemaCatalog.cs:18` 加载, 同时承担服务器入参预验证）。
2. **往返与输出成本**: 浏览一个类型需 `get_type_info`+`list_methods`+`get_type_fields` 3~4 次调用; 调试链每步状态相关调用前都需 `debug_status` 刷句柄（调用翻倍, 情景层被迫在客户端实现 `ctx()` 刷新模式——`tests/scenario/corpus/fam05/workflow.py` 的实证）; `decompile_*` 输出无行数上限; `list_assemblies`/`list_methods` 无 `total_count`（AI 无法判断是否值得翻页）。

问题1结论（已评估）: AI 无需新建 Python 客户端; 增强点 = 在 `dnspy://docs/python-client` 资源补"AI 批处理模式"用法, 引导 AI 在长链路任务切换为"写脚本→执行→读结果"形态（情景层已实证该形态交互 token 为零）。

## 2. 目标与非目标

**目标**: ① `tools/list` 载荷从 ~175KB 降至 ~75KB 量级（`edit_apply` schema 瘦身 + 操作目录移资源）; ② 新增组合工具减少调用往返（`get_type_overview`、`debug_snapshot`）; ③ `decompile_*` 输出可控（`max_lines`）; ④ list 类响应统一 `total_count`、推广 `names_only`; ⑤ python-client 资源补 AI 批处理模式章节。

**非目标**: 不合并/改名/删除任何既有工具（72 工具通告面基线名册不变, 仅为超集扩充）; 不改情景链路测试层语料、账本与已验收基线（其覆盖口径冻结于 P01 快照 72, 历史验收不受影响; 通告面计数变化在文档中说明）; 不引入并行/重试/CI; 不改 MCP 传输、认证与安全语义; 不优化 `*_test_*` 工具。
