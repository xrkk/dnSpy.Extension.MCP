## 3. 实施中发现与处置（net10 调试会话面缺失→修复）

1. **现象**: net10 v1 首测 tools/list=51（32 静态 + debug_capabilities + 18 编辑）, 调试会话工具 21 个全缺; `debug_capabilities` 显示 `dedicated_instance_acknowledged=true` 但 `debug_enabled=false`。
2. **根因链**: v1 宿主取自 `.tmp` R15 构建树 `dnSpy/dnSpy/bin/Release/net10.0-windows/` 裸输出, 该目录**不含** `dnSpy.Debugger.*` 调试器扩展组件（R15 只构建了主程序+契约+MCP 扩展; net48 宿主 `C:\Tools\dnSpy\bin` 则携带 `dnSpy.Debugger.x.dll` 等全套）。`DbgManager` 的导出方在调试器组件中; 组件缺失 → `DebugGateService` 的 `[Import(AllowDefault=true)] DbgManager` 为 null → 启动采样永不落地 → 门"不可采样"恒关（`Debugger/DebugGateService.cs:43-44,63-71`; `McpSettingsStore.cs:166-183` `EffectiveDebugLaunch = DebugToolsEnabled && DedicatedInstanceAcknowledged && StartupDbgWasIdle`）。
3. **修复（子方案 §8 D-01 恢复路径）**: 在同一构建树以 `dotnet build -c Release -f net10.0-windows` 补建六组件（Mono.Debugger.Soft、dnSpy.Debugger.DotNet(.CorDebug/.Interpreter/.Mono)、dnSpy.Debugger; TFM 见 `DnSpyCommon.props:9` `net48;net10.0-windows`, 输出同目录见各 csproj `OutputPath`）, 整体重传替换（v2, 354 文件）, 重启后 net10 tools/list=72 且三族与 net48 一致。v1 保留为 `E:\dnspy-scenario\net10\app-v1-firstupload`（回滚件）。
4. **过程偏差记录**: ① 便携设置路径两次修正（`app\dnSpy\dnSpy.xml`→`app\dnSpy.xml`（net10 生效）→`app\bin\dnSpy.xml`（net48 生效, BinDirectory 规则）, 权威依据 `AppDirectories.cs`; ② v1 打包含无扩展名 `dnSpy` Linux ELF apphost 与设置目录名冲突, 改名让位（DEC-008）; v2 打包时直接剔除; ③ 期间两实例曾短暂以 %APPDATA% 设置运行于 loopback 15378/15379（未产生对外影响, 停止后消除; C:\Tools\dnSpy 与 %APPDATA% 未被修改）。
