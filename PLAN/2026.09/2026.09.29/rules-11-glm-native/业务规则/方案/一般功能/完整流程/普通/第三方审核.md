**阶段 3: 第三方审核**

主会话构造脱离主会话也能完整执行的审核任务包. 直接包含方案、需求来源、生效项目约定、必要代码和证据的路径/版本/blob/稳定 ID 及必要内容、审核范围和对象基线. 对已经提交到 GitHub 的方案, 对象基线必须冻结 repository、commit SHA、tree SHA、方案 path/blob 以及规范性来源、直接依赖和决策关键证据的 blob/指纹; 不要求第三方取得作者本机 `git status`、staged/unstaged/未跟踪状态或本地 HEAD. 只有方案尚未提交时才包含对应本地 HEAD/worktree 基线; 只有结论依赖 self-hosted runner、Docker/GPU、本机数据/服务等运行态事实时才包含相应运行态证据. 定向复审时还必须包含作者持久化的定向复审请求范围和以下完整指令:

1. 你是第三方审核方. 只审核一般功能方案并创建新审计记录; 不修改方案、规范性来源、代码、配置、数据、测试或实施记录, 不提交.
2. 首次审核执行全面审核. 后续只有作者明确判定需要再次审核时才按作者选择的定向或全面模式复审; 你不判断是否需要复审. 定向复审开始前根据请求范围、实际 diff 和历史链输出本轮实际定向复审范围, 至少列出基准记录、未解决/复开 AUD、纳入的章节/路径/受影响通过项/全局不变量、排除与继承项、待回答问题、证据和通过条件. 已提交对象的实际 diff 用基准记录与当前冻结 commit/blob 比较恢复, 不要求本地 worktree diff. 旧请求缺少专用字段时从稳定定位和证据恢复等价范围; 仍无法可靠限定时列证据升级全面审核, 不得只输出需要定向复审.
3. 已提交 GitHub 方案以冻结 commit/tree/path/blob 为权威审核基线; 分支 HEAD 后续前进不改变本轮冻结对象. 缺少作者本机 worktree 或 `git status` 不得单独阻断已提交方案审核. 只有未提交对象或必须由本机/runner 证明的事实才要求相应本地/运行态基线, 且不得用仓库静态证据伪造运行态事实. 固定核心维护、直接依赖、明确排除、决策关键和上下文路径及指纹. 先机械检查身份、来源、稳定 ID、双向追溯、占位符和 fallback, 再逐项语义审查和反例检查; 除关键身份或必要证据不可恢复外, 不在第一条意见后停止.
4. 核对需求无遗漏、曲解或无依据扩张; 功能正常/异常/边界/状态和用户结果闭环; 改动位置、行为、数据/接口、依赖和顺序可直接编码; 决定闭合; ACC 只覆盖目标和受影响直接依赖, 仓库级验证只在明确要求时作为通过条件; 正确性、兼容性、性能、一致性、资源、测试和 fallback 有证据支持.
5. 每条意见引用具体来源或代码证据, 使用跨轮稳定 `AUD-xxx`, 写反例、风险和影响、最小闭合条件、受影响既有通过项和复审证据. 通用最佳实践和泛化风险不能单独形成意见.
6. 在方案同目录创建不可变 `YYYY.MM.DD-NN-{审核|复审}-{方案名}.md`; 首次第三方审核选 `审核`, 后续再次审核选 `复审`. 记录对象身份、审核性质/模式、仓库审核基线 commit/tree、范围、覆盖清单、意见和结论; 仅在实际使用本地/runner 运行态证据时另记对应环境与运行态基线; 未提交对象则记录其本地基线. 定向复审另外记录本轮实际定向复审范围及其逐项覆盖结果. 结论只允许 `审计通过`、`存在不同意见`、`审核循环熔断` 或 `审计被阻断, 未形成有效结论`; 持久化失败单独报告.
7. `存在不同意见` 不决定作者引入后是否再次审核, 不输出下一审核模式, 不主动提出继续执行定向复审. 写完记录后返回记录路径/blob、覆盖、意见、结论和阻碍并结束.

主会话按本入口的审核与执行协议交付本阶段上述全部编号指令, 核对独立审核者身份、冻结对象、模式、覆盖、结论和审计记录已真实持久化; 不接受口头结论替代记录.
