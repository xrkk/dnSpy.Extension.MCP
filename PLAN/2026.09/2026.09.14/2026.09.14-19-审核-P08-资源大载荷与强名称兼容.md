## 3. 语义审查关键判定

- **J1（只新增种类合规）**：6 新操作全部经 `edit_apply` 既有信封/审查/提交/检查点/逆链，落点＝`EditOperationRegistry` 新 case（P04/P07 扩展点先例）；IMP-006 计数（36/17/25/oneOf 6+2/ACCS）与代码现值逐项吻合。导入导出两入口为总纲 §5.1 明确要求的资源级 I/O 面，未复制程序集导出。**合规**。
- **J2（CON-019 边界可行性）**：标准条目域经 `ResourceReader` 只读枚举+`ResourceWriter` 重建，自定义对象仅类型名/长度/SHA 查看与整体字节替换，含 ACC-007 双层哨兵（harness 探针类+VM 恶意 fixture）——与 CON-019 行 105、NON-007、§5.3 行 181 一致。**边界成立**；但标准值域冻结不精确（AUD-006），且 `ResourceWriter` 字节级确定性风险未被方案识别（AUD-003）。
- **J3（Win32 面现状——本轮核心反例一）**：`EditFingerprint.Projection`（`EditFingerprint.cs:83-129`）只枚举 `module.Resources`（托管清单资源），**`module.NativeResources`（Win32 行）完全不在投影内**（语义指纹与 roundtrip 指纹双盲）。后果：(a) §2"资源操作天然改变指纹（与 P07 不同，无需投影变更）"对 `win32_resource_add/remove` 不成立——Win32 操作不改任何指纹行；(b) CON-004 live 冲突检测对事务期间 UI 修改 Win32 行盲（P07 AUD-002(c) 同型既有盲区，P08 引入专门操作种类后成为方案必须处置的声明缺口）；(c) review 的 roundtrip 校验（`EditWorkspace.cs:96-106`）对 Win32 行盲；(d) 唯一既有覆盖是**图像通道**——检查点 `ResultImageSha256`（写出 PE 含原生段）与重放分类（`EditHistoryModule.cs:578-580`：image+semantic 双比对，image 不等即不 exact）字节级覆盖 Win32 行；(e) P07 已裁定投影扩展会退化既有谱系（`…-15` AUD-001 处置：撤回投影扩展，改三层覆盖＝图像 SHA+review 身份断言 `EditTransactionCoordinator.cs:560-594`+harness 图像级断言），该先例在本仓库是**唯一已裁定的兼容路线**。方案 §6.3 把"三层覆盖先例 vs 投影扩展"留作审核问题未决定——方向性决定未闭合（AUD-001）。
- **J4（file_id 载荷与 P03 包机制兼容——本轮核心反例二）**：检查点包已有载荷池（`payloads/<sha256>.bin` 按 SHA-256 去重，`EditHistoryModule.cs:768-777` 校验；`EditSerializedOperation.PayloadSha256` 引用），但载荷**提取与校验按操作种类硬编码白名单**（`:871` `kind is "method_body_replace" or "method_add"`；`:905-906` 读回侧同限制）——资源种类当前无法携带包载荷。`IEditCheckpointStore`（`EditCheckpointStore.cs:17-28`）只有包/输出写入与原子替换接口，**无"VM 外部路径读取+载荷登记"面**；其 `file_id` 是 NTFS FileIndex 输出身份（`:277-290`），非输入载荷注册表。故 §1.2/§2"复用 P03 checkpoint store 的文件身份机制"的"复用"对 import 语义失实——需新增导入暂存机制。总纲 §5.2 行 175 已冻结"按 SHA-256 去重的源代码/**资源**载荷"入包——即"字节快照入包（payload_sha256 引用）"是唯一与冻结契约一致的答案，方案未写明信封形态、白名单扩展落点与 ACC 恢复断言（AUD-002）。逆状态捕获大字节与 `MaxNormalizedOperationBytes`（8 MiB，`EditContracts.cs:14`）的容量交互同样未声明。
- **J5（标准条目重建三面一致性——本轮核心反例三）**：方案承诺"重放确定性：全部载荷驱动（条目重建的字节流由载荷决定；写出设置固定 normalization）"，同时把"对齐/版本头"归为实现细节且判据为"以重载读回一致为准"。技术事实：`System.Resources.ResourceWriter` 写出的 `.resources` 名字哈希表字段源自运行时字符串哈希函数，条目排序亦按该哈希——net48 默认跨进程确定，**net10（本方案双 TFM 之一，CON-018）字符串哈希每进程随机化**，跨进程（dnSpy 重启后恢复/重放检查点）重建字节不可复现；而指纹 resource 行与重放分类均为**字节/SHA 级**（`EditFingerprint.cs:126`；`EditHistoryModule.cs:578-580` semantic 含 resource SHA）。若跨进程字节漂移，含条目级编辑的检查点将分类 `unverified_drift`（semantic 即不等，连 validated_drift 都不可达）→ 按 CON-023 仅诊断、不可恢复/导出。值级判据（读回一致）不能替代字节级判据；该风险未被方案识别，且与自身"载荷驱动"承诺矛盾（AUD-003）。

## 6. 结论

**存在不同意见**（含三条阻断级发现：AUD-001、AUD-002、AUD-003 均为"不可验收＝阻断"级；方案 v0 在其闭合前不得进入实施，状态保持 `未审核, 不得实施`）。

本轮通过项：对象身份与前置链（P07 `0068254`/`0cd84c3` 实证）、只新增种类复用 P02/P03（§12 行 412 合规，含资源级 I/O 非第二导出面的边界论证）、ACC-007/008/016 与总纲行的五列逐条对应及多处强化（"不提高上限""要求人工放置＝失败""无失败即移除＝失败"、双哨兵、断链拒绝）、CON-019 硬边界设计、两个 fallback 均为总纲 §7 既有项、无后序依赖、操作计数链 30→36 与 validator 现值逐项吻合、ACC 命令/输入/预期/证据/边界五要素与 run-id 前缀 `p08-resource-` 合规。

本轮不通过项（阻断级）：AUD-001——Win32 行完全不在指纹投影内使 §2"无需投影变更"断言失实，覆盖机制（P07 三层先例 vs 投影扩展）这一已由前案裁定的方向性决定未闭合，CON-004 冲突检测对 Win32 面盲且无验收守门；AUD-002——file_id 载荷在检查点信封中的形态与重放取字节语义未闭合，"复用 P03 文件身份机制"失实（`EditHistoryModule` 载荷白名单硬编码、store 无导入面），ACC 无含 file_id 检查点的恢复/重放断言；AUD-003——标准条目重建的跨进程字节级确定性（net10 名字哈希随机化）未保障，被错误归入纯实现细节且"重载读回一致"判据低于指纹/重放机制的字节级要求。三案分别落在 Win32 面、大载荷面、标准值面，须各自闭合。另有 AUD-004（强名称证据链归因判据与防伪属性）、AUD-005（Win32 替换/导入导出未落点）、AUD-006（标准值域冻结）三项中级与 AUD-007/008 两项低级修订项。
