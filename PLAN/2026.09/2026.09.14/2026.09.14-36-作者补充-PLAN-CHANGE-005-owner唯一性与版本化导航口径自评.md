## 1. R03 修正事实（对 35 号记录与 R02 交付的更正）

- **F1/B1 重复 owner 必须 fail-closed**：R02 的强投影对“同一模块两个同名 type（结构化 owner 相同）”或“同一 type 两个同名同签名 method”会产出稳定 hash，互换方法体后 hash 不变，等于静默合并歧义输入。R03 在强投影内对模块级 type owner 与全模块 method owner 做唯一性检查，重复即 `EDIT_CAPABILITY_UNAVAILABLE`，输入不变；合法重载、不同 type、modreq/scope 差异仍通过。Codex 反例已复跑：`ambiguous-owner rejected=EditDomainException`（`T003-R03-B1-codex-counterexample.log`）。
- **F2/B2 循环与深度**：强投影此前的 `JsonSerializer` 编码与历史 `Sig`/`FullName` 辅助都没有环/深度守卫，畸形 TypeRef scope 环、FnPtr 签名环（含 FnPtr 指向非 MethodSig）、自嵌套 TypeSpec、自嵌套 DeclaringType 会导致栈溢出、无限分配或把非 MethodSig 静默写成 null；深度较大时还会触发 JSON 64 层上限。R03 将强投影完全切到带环检测与 2048 层显式上限的结构化文本编码，且不再在强路径调用无守卫的历史渲染/序列化路径。隔离子进程实测（`T003-R03-B2-cycles.log`）：5 类畸形环全部 `EDIT_CAPABILITY_UNAVAILABLE` 且无崩溃/挂起；40/1000/2000 层合法签名正常计算；2049 层按文档上限显式失败。
- **F3 正式回归进入仓库**：新增 `tests/edit/P03StoreHarness/OwnerVersionProbe.cs`（模式 `--owner-version`）与 `tests/edit/P03StoreHarness/fixtures/legacy-v1/`，固定旧包与旧算法向量随仓库提交，干净 checkout 可独立重跑，不依赖 `/tmp` 或 RUN 路径。临时 runner 不再是交付。
