- 证据：v11 TYPE-DYN-010 和 API-DYN-001 字段互相一致；ACC-002/022/028/029 分别在 x86/x64 host 断言同位数 3 项可用、异位数 3 项不可用且 Start/claim/session 增量为 0。

### AUD-018：BFS 跨页父引用

- 处理结论：同意。
- 层级：当前方案公共 ValueNode/分页契约。
- 理由与证据：上游只提供根数组和逐 parent 的直接子节点；A、B、C、A1 在 `page_size=2` 时证明“父必须在同一响应”和 BFS 无重漏不可同时满足。
- 实际修改位置：v9/v10 的 TYPE-DYN-007、API-DYN-020/021、IMP-008、ACC-015/016/028 把 parent 作用域固定为同一 immutable snapshot 中更早的 BFS 序列，允许父位于前页，客户端保留已见 handle，服务端不重复父节点。v11 不再改变该行为。
- 证据：ACC-015/016 固定第一页 A/B、第二页 C/A1，A1 指向第一页 A；同时断言无重漏和后续页不重新求值。

- 复审请求：纳入全面复审，重点复核 schema 条件与逐页 canonical fixture。

### AUD-019：snapshot 与 value_handle 生命周期

- 处理结论：同意。
- 层级：当前方案资源、对象所有权和公共句柄契约。
- 理由与证据：v8 没有区分 page snapshot 与已返回 handle；最终页关闭 handle 会破坏 expand，保留而无总预算会绕过 2-slot。
- 实际修改位置：v9/v10 的 CON-DYN-009、TYPE-DYN-007/017、API-DYN-001/020/021、IMP-004/008、ACC-004/015/016/028 固定：物化时预分配；canonical page 完成时转移本页 handle；最终页只销毁 snapshot/cursor/slot；每 pause_epoch 的 snapshot-owned + returned 总量不超过 4096；达到上限返回 `value_handle_limit` 截断；创建/序列化失败关闭未转移对象；epoch 结束两类各 close-once。v11 不再改变该行为。
- 证据：TYPE-DYN-007 的 `has_children/is_null/unavailable_reason/value_handle` 条件闭合；ACC-016 覆盖最终页后 expand、旧 cursor、第三 snapshot、放弃 snapshot、4096 累积和准确 close 计数。
- 最小闭合条件：满足；正常 expand 与资源上界不再二选一。
- 复审请求：纳入全面复审，重点复核所有权转移原子点、失败回收和 response 写失败边界。

### AUD-020：WPF 与 DbgManager 线程边界

- 处理结论：同意。
- 层级：当前方案架构和线程所有权契约。
- 理由与证据：EVD-API-007 显示 `DbgManager.Start` 可由调用线程进入，随后异步投递 `Start_DbgThread`；v8 的“全部只经 DbgManager dispatcher”与 WPF claim/precheck/Start 规则冲突。
- 实际修改位置：v9/v10 的 CON-DYN-003、3.2、IMP-001/004/005、ACC-001/034 固定唯一例外：initial/restart 的一个 WPF callback 只操作不可变 launch DTO、线程安全 reservation/claim、`IsDebugging` 和 `Start`；不得读取/持有调试对象；事件、匹配、建权、状态、句柄和值全部在 DbgManager dispatcher。v11 不再改变该行为。
- 证据：ACC-001/034 分别要求 WPF outer 和 DbgManager inner probe，并把任一 WPF 调试对象访问或未声明 Start 位置列为失败。
- 最小闭合条件：满足；实现者没有并列线程解释。
- 复审请求：纳入全面复审；这是架构变化，必须从线程安全和所有权关键路径重新审核。

### AUD-021：设置 durable commit 与崩溃恢复

- 处理结论：同意。
- 层级：当前方案数据一致性、安全、持久化和迁移/切换策略。
- 理由与证据：EVD-CODE-003 证明现状不是事务；v8 candidate-first 后回写 old 的协议在 transition 与回写双失败时可让未成功应用的 candidate 在重启后生效。
- 实际修改位置：v9/v10 的 CON-DYN-014、IMP-003、ACC-036 固定 `SettingsPendingJson` staged 与 `SettingsSnapshotJson` committed，顺序只能是 pending→server transition→committed→memory/event→clear；启动只激活 canonical 11-field 且通过完整语义/lease 验证的 committed；孤立/不同/无效 pending 不生效；失败恢复 old server 或强制 Stop，禁止回写 old JSON。v10 进一步固定 invalid committed、legacy 和 pending-cleanup 的启动验证/提示。v11 不再改变该行为。
- 证据：ACC-036 覆盖 pending 写、transition、committed 写、clear、old-server 恢复的故障注入，以及每个指令边界崩溃和 pending/committed 启动矩阵；逐项断言存储、server、memory、event 和 modal/log。
- 最小闭合条件：满足；任何未写 committed 的 candidate 都不能因清理失败或重启被激活。
- 复审请求：纳入全面复审；持久化与迁移/切换策略已改变。
