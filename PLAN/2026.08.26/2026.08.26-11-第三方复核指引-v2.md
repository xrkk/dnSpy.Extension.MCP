## 3. 复核步骤

### A. 仓库与构建门禁（Linux）
```
git status --short        # 除 PLAN/dnSpy-MCP.md（用户自有）外应为空
DNSPY_DIR=<dnSpyEx> bash tests/run-verify-local.sh
```
预期：`ALL CONTRACT CHECKS PASSED`、`net48 dependency guard PASSED`、双 TFM 0 警告 0 错误、`LOCAL VERIFY PASSED`。记录 net48 DLL SHA-256（B 步比对）。

### B. 部署一致性（VM）
DLL 与 `git bundle` 传输后**哈希逐字节比对**；repo 克隆后 `git log -1` 应为被复核提交。

### C. 单次连续 36 案批跑（VM，核心程序）
按 v1 指引 C 节循环原样顺序执行 36 案（驱动在案与案之间强制冷启动）。**判定三要素**：
1. 每案 `result.json`（`tests/debug/results/<HEAD-sha>/<case>/`）`exit_code==0` 且断言全 pass；
2. 36 个 result.json 的 `commit_sha` **全部等于同一 HEAD**（连续性——历史上"跨轮拼图"曾伪造 36/36，此为针对性检查）；
3. `result-evidence-complete` 与 `result-schema-shape` 两门禁在每案通过（驱动内置，无需手工）。
预期耗时约 13–15 分钟；002/003/023 有远程模式段、036 有约 60 秒静默等待，均属预期。

### D. 关键点抽检（每项 1–2 分钟）
- `a25-ctl-terminate`（025）→ `OWNERSHIP_LOST` 且 `a25-no-unowned-operation` 发帖增量 0；
- `a33-lease-share-conflicts`（033）→ 五类替换企图全部 share 冲突且字节不变；
- `a16-stale-handle`（016）→ continue 后旧 value_handle `STALE_HANDLE`；
- `a08-apphost-launch`（008）→ `ok=True mode=coreclr-apphost`（检测器 apphost 豁免）；
- `a4-body-limit-413`（004）→ 恰 1 MiB 非 413、+1 字节 413；
- `a24-unity-over-limit`（024）→ 超限证据 `INTERNAL_ERROR` 无 details。

### E. 反空转与反拼图检查（本版新增/强化）
1. **虚假闭合检查**：任取整改声明（实施记录第 62–64 轮、闭环状态 JSON `rectification`），逐条对照其声称修改的落盘 diff——历史上两次"声明已改、实际未写"（CHK-007/009）均由此捕获；
2. **批跑连续性**：C.2 的 commit_sha 一致性 + 时间戳无重叠（ZCode 记录 §2 的三协议 R1/R2/R3 可复用为方法学）；
3. **提交描述与 git 事实交叉**：整改链 14 个条目逐一对 `git log --format=%s`（CHK-012 教训）；
4. `debug_test_*` 六工具仅 DNMCP_TEST=1 广告（无该变量启动 dnSpy 后 tools/list 计 0）；
5. 挂账披露核对：第 5 节清单逐项在册。

## 4. 判定标准

- **通过**：36/36 连续批跑 exit 0（commit_sha 同一）+ D 抽检一致 + E 无空转/拼图/虚假闭合发现。
- **部分通过**：个别失败可归因于环境（无管理员权限等）——逐条注明后可对非环境项给出通过意见。
- **不通过**：任何非环境性失败，或 E 节任一发现。
