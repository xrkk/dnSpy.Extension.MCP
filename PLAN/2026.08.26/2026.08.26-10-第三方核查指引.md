# dnSpy MCP 托管动态调试增强方案 — 第三方核查指引

- 文档目的：供独立核查方在不依赖被核查方口头陈述的前提下，复现并裁定方案落地情况。
- 被核查主张（截至本文件提交时）：
  1. ACC-001..036 共 36 项验收 case 全部在 Windows VM 实跑 `exit 0`（零失败断言）；
  2. IMP-001..011 全部落地；
  3. 实施过程中共 49 项产品修复，逐项记录于实施记录轮次日志；
  4. 其中 7 项 case（003/004/019/020/027/029/036）为**记录了明确缺口的实车子集**（非全契约覆盖，缺口清单见第 5 节）。
- 基准提交：`8599fae`（docs: 第 60 轮收官）。核查应从该提交或其后的修复提交出发。

## 1. 可核查性边界（先读）

- **可独立复现**：构建门禁、36 项 case 的 E2E 执行、全部断言与 wire 证据的再生成——均只依赖仓库内容 + 标准Windows VM，不需要被核查方参与。
- **需要信任假设的部分**：
  - 历史轮次的运行证据（`tests/debug/results/<HEAD-sha>/<case>/`）由被核查方执行产生，留存于 VM `C:\Tools\mcp-repo\tests\debug\results\`；核查方可调阅比对其与实施记录的对应关系，但**裁定应以核查方自行复跑的结果为准**；
  - 实施记录中的“产品修复 N 项”为过程性叙述，其可核查对应物是当前代码与各 case 断言，而非历史中间态。
- **本指引不要求**核查方相信任何日志文本；所有判定输入均为核查方自己机器上新生成的 `result.json` 与 wire 证据。

## 3. 核查步骤

### A. 仓库与构建门禁（Linux）
```
git status --short                 # 除 PLAN/dnSpy-MCP.md（用户自有文件，范围外）外应为空
DNSPY_DIR=<dnSpyEx源树> bash tests/run-verify-local.sh
```
- 预期输出包含 `ALL CONTRACT CHECKS PASSED`、`net48 dependency guard PASSED`、双 TFM `0 个错误`、`LOCAL VERIFY PASSED`。
- 记录 `dist/dnSpy.Extension.MCP-net48.x.dll` 的 SHA-256（步骤 B 校验用）。

### B. 部署一致性（VM）
- 以任意方式把上一步 DLL 与 `git bundle` 传到 VM；部署后必须比对哈希与构建机一致。
- repo 在 VM 克隆至 `C:\Tools\mcp-repo`，`git log -1` 应为被核查提交。

### C. 全量 36 案复跑（VM，管理员 PowerShell）
```
cd C:\Tools\mcp-repo
foreach ($c in ('ACC-001','ACC-002','ACC-003','ACC-004','ACC-005','ACC-006','ACC-007','ACC-008','ACC-009','ACC-010','ACC-011','ACC-012','ACC-013','ACC-014','ACC-015','ACC-016','ACC-017','ACC-018','ACC-019','ACC-020','ACC-021','ACC-022','ACC-023','ACC-024','ACC-025','ACC-026','ACC-027','ACC-028','ACC-029','ACC-030','ACC-031','ACC-032','ACC-033','ACC-034','ACC-035','ACC-036')) {
  powershell -NoProfile -ExecutionPolicy Bypass -File tests\debug\run-debug-tests.ps1 -Case $c
  # 退出码 0 = 全断言通过；每案产物 tests\debug\results\<HEAD-sha>\<case>\result.json
}
```
- 判定输入：`result.json`（schema `dnspy.debug.test.v1`）的 `exit_code == 0` 且 `assertions[].status` 全为 `pass`。
- 驱动自行管理 dnSpy 生命周期（含 x86 宿主切换，ACC-029）；无需手工干预。
- 注意：ACC-002/003/023 会短暂把服务器切到远程模式（15100 + Bearer）并在结束时恢复 loopback；ACC-036 含一次约 60 秒的“服务器静默”等待，属预期。
- 耗时约 2 小时量级；结果目录按 HEAD sha 隔离，可与历史运行并存。
- **VM 服务无需预先启动**：驱动自行拉起/重启 dnSpy（含设置快照写入与进程清扫），核查方只需能以管理员在该 VM 上运行 PowerShell；3000/15100 当前未监听不构成阻断。
- 自第 61 轮起，`exit 0` 除断言全过外还要求：每条断言引用的证据文件实际存在（`result-evidence-complete` 门禁）且 result 满足 `tests/debug/contracts/dnspy.debug.test.v1.schema.json` 形状（`result-schema-shape` 门禁）。

### D. 关键修复抽检（可选，每项 1-2 分钟）
从复跑证据中抽查以下断言是否真实非空转（断言 id → 应观察到的实际值形态）：
- `a25-ctl-terminate`（ACC-025）→ `code=OWNERSHIP_LOST`，且 `a25-no-unowned-operation` 的 break/terminate 发帖增量为 0；
- `a33-lease-share-conflicts`（ACC-033）→ 五类替换企图全部 share 冲突且字节不变；
- `a35-module-scoped-hits`（ACC-035）→ 连续 HIT 全为同一 bp id，spy 键含两个相异的 `"SatelliteLib.dll (id=N)"`；
- `a16-stale-handle`（ACC-016）→ continue 后旧 value_handle 为 `STALE_HANDLE`；
- `a24-unity-over-limit`（ACC-024）→ 超 1024 字节证据值为 `INTERNAL_ERROR` 且无 details；
- `a4-body-limit-413`（ACC-004）→ 恰 1 MiB 与 1 MiB+1 的分界行为。

### E. 反空转检查（建议）
1. 任取一案，确认其断言计数 > 0、失败时会真的 `exit 1`（可故意改坏一处断言验证驱动 fidelity）；
2. 确认六个 `debug_test_*` 工具仅在 `DNMCP_TEST=1` 下广告（无该环境变量启动 dnSpy 后 `tools/list` 不含它们），生产路径不受注入面影响；
3. 确认 case 的证据路径（`evidence_paths`）指向实际存在的 wire/JSON 文件；
4. 对照实施记录“ACC 状态表”逐行核对状态与退出码声称。

## 4. 判定标准

- **通过**：36/36 复跑 `exit 0`，且 D 节抽检一致，且 E 节无空转发现。
- **部分通过**：个别 case 失败但可归因于环境（如缺管理员权限导致 002/003/023 的远程段失败）——需在核查记录中逐条注明。
- **不通过**：任何非环境性断言失败，或发现断言空转/证据造假迹象。

## 5. 已声明的部分覆盖与挂账（核查方应知悉，不构成隐藏）

以下 7 案为实车子集，其未覆盖部分已在实施记录（第 59/60 轮“挂账缺口”）逐项声明：
- ACC-003：七类端点中 SSE/Streamable 为传输层同墙（在役传输已验）；null peer 注入未实现；
- ACC-004：17th transport session / 9th long / 伪小 Content-Length / chunked 未驱动（HTTP 16 槽为传输层）；
- ACC-019：quota at/over（128 会话/4096 child/8 GiB）与 CreateNew/cancel 时间线需 IArtifactIo 故障 seam；
- ACC-020：dnSpy 用户断点快照对照（UIA）未接；
- ACC-027：ownership-lost 的 UI 注入变体（已由 ACC-025 的 foreign_process 注入路径覆盖等价语义）；
- ACC-029：coreclr-x86 正例（需 x86 dotnet host，失败关闭分支已验）；x86 harness 正例；
- ACC-036：严格未知字段拒绝、pending 写故障注入矩阵、双实例隔离（共享 dnSpy.xml 设置存储）。

其余过程性挂账（缓存跨协议按版本重渲染、il_offset 方法体边界、静态工具 outputSchema、模块 MVID 真值）同样在册。
