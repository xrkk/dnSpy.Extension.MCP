## 3. AUD-023 处理

- 处理结论：`同意`。
- 严重性：高。
- 问题归类：当前方案安全/数据一致性契约缺口；不是上层需求变化，也不是纯实现细节。
- 理由：CON-DYN-008 marker 的全部字段都可被具有同用户写权限的进程构造或复制；final path/file ID 只证明当前对象身份，不能证明创建者。继续保留跨重启自动删除无法满足 RACC-DYN-007 的“只处理自有数据”目标。现有来源没有要求自动回收，因此取消扩展侧删除是唯一不扩大信任机制、且能在当前 threat boundary 内机械闭合的方案。
- 实际修改位置：方案 1.3 新增 SRC-AUD-005；CON-DYN-008 及其全局配额补充段；RACC-DYN-007；IMP-009/011；ACC-019/022；第 7 节 fallback 边界；v12 变更记录和审核重点。
- 固定修改：marker 仅用于当前 active writer 校验和只读统计，不再是跨重启所有权证明；全部 pre-existing session/child 无条件标为 `stale_untrusted`；扩展不得请求 child DELETE access，也不得自动删除、移动、覆盖、截断或提供 cleanup API；未知/超额只 fail closed；唯一退出是停止扩展后由操作者人工移出/删除并重启。
- 证据：原审计 AUD-023；REQ-DYN-010/011、CON-DYN-008、RACC-DYN-007；EVD-OS-001 的对象身份能力边界；v12 blob 中 CON-DYN-008、IMP-009、ACC-019 的一致规则。
- 最小闭合条件：满足。ACC-019 固定覆盖结构合法伪 marker、复制旧 marker、新建伪 session、真实过期 session 注入普通文件四类反例，要求扩展 DELETE/move/truncate/overwrite 调用增量全部为 0，并验证人工退出流程与扩展调用身份分离。
- 复审请求：确认取消 cleanup 后，quota 重扫、fail-closed、人工退出和部署文档没有隐藏删除路径，四类强反例能够机械验收。

## 4. AUD-024 处理

- 处理结论：`同意`。
- 严重性：高。
- 问题归类：当前方案 lifecycle/资源/验收契约缺口；不改变 launch-only 上层范围，但改变协调器线程和状态契约。
- 理由：上游 Break/Terminate 的 void 返回不能证明完成；没有 deadline 会永久占用 cache in-flight Task、命令队列和非 idle coordinator。既有 TYPE-DYN-011 已有 TIMEOUT/INTERNAL_ERROR，故以固定 control record 和事件完成门闭合，无需修改 dnSpy 核心或引入不受来源支持的后台重启 fallback。
- 实际修改位置：新增 EVD-API-011、SRC-AUD-005；CON-DYN-003；3.2 control operation、状态和 recovery；API-DYN-001/006/008/009/011；EVT-DYN-021 及 schema；3.6 状态表和转移；IMP-002/004/005/011；ACC-007/008/022/028/034；第 7 节、v12 记录和审核重点。
- 固定修改：API-DYN-006/008/009 出队即建立 30 秒 monotonic `ControlOperationRecord`，以 scheduled/issued/settled phase 和 compare-and-swap 让正常事件、explicit_failure、deadline 只结算一次；TIMEOUT/INTERNAL_ERROR 写恰好一个 EVT-DYN-021并封口缓存响应。pause 失败保持 running；terminate/restart 未 issued 恢复 prior_state；issued 后失效 handle、保留 confirmed-owned process/session并 faulted，restart 释放 reservation且禁止 Start/新 generation。只有实际观察 owned process 移除才 terminal；所有迟到事件按 session/generation/control_epoch/owned identity fencing。
- 证据：原审计 AUD-024；REQ-DYN-004、CON-DYN-003/004/009/012/013、RACC-DYN-004；EVD-API-001/007/011；v12 的 API/EVT/state/IMP/ACC 契约。
- 最小闭合条件：满足。ACC-007/008/034 与 schema fixture 固定覆盖 Break explicit failure、Break 永不完成、Terminate 永不 disconnect、29.999 秒完成、30.000 秒 deadline、deadline 后迟到 paused/disconnect、restart 旧进程不退出和 terminate 重试；每项都有唯一 response、state、event、cache/queue/reservation/handle/process 计数、恢复步骤，并给 driver 120 秒 wall-clock timeout。
- 复审请求：确认 deadline 起点包含 dispatcher 排队、timer 不访问 dnSpy 对象、scheduled/issued 分支唯一、faulted 两种原因不能混淆、迟到事件不能改写响应或复活 restart，以及所有资源计数必然结算。
- 审核循环熔断：不触发；AUD-024 为首次处理。
