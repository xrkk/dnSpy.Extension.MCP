## 4. 审计意见

### AUD-006：同一公共 schema 对 debug_context 和 cursor 给出互斥定义

- 严重度：阻断性。
- 来源或方案 ID：REQ-DYN-003、REQ-DYN-005、REQ-DYN-006；CON-DYN-013；RACC-DYN-002、RACC-DYN-011；方案 3.4、3.5；TYPE-DYN-001、TYPE-DYN-002；API-DYN-011/012；EVT envelope；IMP-002；ACC-002、ACC-005、ACC-028。
- 已证实问题：
  1. 3.4 宣称成功对象及字段全集固定，但示例 debug_context 只有 session_id/generation/pause_epoch/event_cursor；TYPE-DYN-001 又把 state 定义为未标可选的必填字段。
  2. 3.5 总则把 “handle/session/cursor” 全部定义为无填充 base64url opaque string；同节 TYPE-DYN-001 的 event_cursor、API-DYN-011 的 after_cursor=0 和事件 envelope 的 cursor 却要求数值单调游标。page cursor 与 event cursor 没有被规范性区分。
  3. ACC-018 给出四类非法输入，却只列 LIMIT_EXCEEDED/非法参数/INVALID_STATE 三类结果，没有精确固定模块范围外输入对应 API-DYN-023 的哪一错误。
- 风险：JSON Schema 2020-12、handler DTO 和 canonical fixture 无法同时逐字满足所有条款；两个独立实现可产生不同 wire contract，直接违反 RACC-DYN-011。
- 影响：公共协议、双向追溯的语义落点、决策闭合和 ACC-028 的通过边界均不成立。
- 建议：明确 3.4 的 debug_context 恰为 TYPE-DYN-001 并补 state；把 page_cursor 固定为 opaque string、event_cursor/after_cursor 固定为非负 integer，逐字段改名或给出互斥定义；为 ACC-018 四个输入逐项固定错误码和无副作用断言。

### AUD-007：恰好一个身份匹配 process/runtime 不能证明它由 MCP 的 Start/Attach 产生

- 严重度：阻断性安全问题。
- 来源或方案 ID：REQ-DYN-004、REQ-DYN-012；CON-DYN-004、CON-DYN-012；RACC-DYN-004；方案 3.2、3.6；IMP-004、IMP-005；ACC-025、ACC-027、ACC-034；EVD-API-007。
- 代码证据：DbgManagerImpl.cs blob 841ba23fa194df7156878542b167b01edb825f55 的 Start 在 302—326 行创建 engine 后只把 Start_DbgThread 排入 debugger dispatcher 并立即返回；338—365 行稍后追加 engine 并调用 engine.Start。DbgManager.cs blob e1c907ebc532b2b66e71a57d86fd1c271f6fd00e 的公开 process/runtime 事件不携带本次 Start 的调用方 token。DebuggerImpl/UI Attach blobs 48331f…、46c002…、9c78bd… 可直接调用同一 Start，且不共享 MCP reservation。
- 已证实问题：若 UI 在 claim 窗口启动完全相同 path/file ID/runtime/architecture 的目标，而 MCP engine 随后失败、超时或没有形成第二个可观察对象，快照差集中可能只剩一个完全匹配的 UI process/runtime。当前规则会把它当成 owned；身份相同只证明“是什么”，不证明“由哪次 Start 产生”。attach 同样可能在 UI 与 MCP 同时附加同一 PID/runtime 时出现单一匹配 runtime。
- 测试缺口：ACC-034 只在 barrier 中触发一次 UI Start 并检查 0/多/不匹配歧义，没有要求“UI 启动同一 target + MCP Start 失败/目标早退后仅剩一个匹配对象”和“UI/MCP 同时 attach 同一 runtime”必须零建权。
- 风险：MCP 可能暂停、继续、终止或分离人工 UI 建立的会话，违反核心所有权和不影响人工会话边界。
- 影响：上一轮 AUD-005、RACC-DYN-004 及所有 lifecycle 控制仍未闭合。
- 建议：提供由可用公共契约承载并能从 process/runtime 事件反向验证的因果 identity，而不只比对目标文件身份；若 dnSpy v6.6.0 公共 API 无法提供该证明，则把并发 UI Start/Attach 作为 launch/attach 的不可实现阻断条件，不得以“恰好一个同身份对象”建立所有权。ACC-034 必须加入上述单一幸存同身份和同 runtime attach 竞争场景。

### AUD-008：restart 在同一规范中既保持 session，又公开经过允许新 launch 的 idle

- 严重度：阻断性。
- 来源或方案 ID：REQ-DYN-004、REQ-DYN-006、REQ-DYN-012；CON-DYN-004、CON-DYN-012；RACC-DYN-002、RACC-DYN-004、RACC-DYN-008；方案 3.2、3.6；IMP-004、IMP-005、IMP-010；ACC-020、ACC-027、ACC-034。
- 已证实问题：3.2 规定 restart 终止旧 process 时不写 EVT-DYN-020，session 保持 restarting/stopping；3.6 却固定公开转移 restarting→stopping→idle→starting。同一状态矩阵允许 idle + launch/attach，IMP-010 也只在 coordinator state != idle 时阻断六个静态写工具。
- 风险：在旧 process 已退出、新 generation 尚未 Start 的窗口，第二个 launch/attach 或静态 mutation 可按现有文字合法进入，破坏“最多一个 session”、restart reservation 和调试期间静态写阻断。
- 测试缺口：ACC-034 验证 EVT-DYN-004/无 EVT-DYN-020 和新 generation，但没有在 post-exit/pre-Start barrier 中并发调用 launch、attach 与六个静态写工具。
- 影响：状态变化、并发顺序、用户可见状态和资源所有权不能机械编码。
- 建议：删除 restart 的公开 idle 转移，或明确该 idle 是不可观察内部子状态且唯一 reservation、active session 与 mutation gate 始终保持占用；在 ACC-020/028/034 增加该窗口的并发拒绝矩阵。

### AUD-009：三种 MCP protocolVersion 的动态结果兼容规则和验收缺失

- 严重度：高。
- 来源或方案 ID：CON-DYN-005；RACC-DYN-001、RACC-DYN-011；方案 3.4、IMP-002、IMP-011；ACC-001、ACC-002、ACC-028；McpServer.cs blob 8bb061aee61492cc2a080829d2f7b0ec2c54785c；EVD-MCP-001。
- 规范证据：MCP 2025-06-18 changelog 明确“Add support for structured tool output”；2024-11-05 和 2025-03-26 的 tools 规范没有 structuredContent，2025-06-18 才定义 structuredContent/outputSchema 与 text 兼容要求。当前 McpServer 仍会协商全部三版。
- 已证实问题：3.4 只说 structuredContent 可选，没有固定按协商版本何时省略、2025-06-18 是否在 tools/list 发布 outputSchema，也没有规定旧版本只返回 content/isError。ACC-002/028 未按三个 protocolVersion 分别验证 tools/list 和成功/领域失败 tools/call。
- 风险：实施者可能向旧协议客户端发送其版本不存在的结构化字段，或三个版本产生不一致错误/文本语义；仅靠现有静态 E2E 无法证明新增 25 个动态工具兼容。
- 影响：CON-DYN-005 的三版本兼容和发布门禁不完整。
- 建议：固定版本矩阵：2024-11-05/2025-03-26 只发送规范允许的 content/isError；2025-06-18 明确 structuredContent 与 outputSchema 行为，文本副本深比较一致；ACC-002/028/022 对三版分别执行 tools/list、成功和领域失败 fixture。
