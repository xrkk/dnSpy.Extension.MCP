## 2. AUD-025 处理

### 2.1 判断

- 处理结论：同意。
- 风险：高。
- 问题层级：当前方案实施/验收契约缺口，不是上层需求变化，也不是可留给实施者的纯类拆分细节。
- 理由：本地 `control_epoch` 在上游事件中不存在，不能证明 paused/removal 属于旧请求还是当前请求。v12 以较新 epoch 丢弃真实 paused 的规则与已证实公共契约冲突，审计给出的 P1→P2 反例成立；terminate retry 的 removal 仲裁也未唯一闭合。

### 2.2 实际修改位置

- 1.2 `EVD-API-011`：加入 paused/removal 无 request、operation、control_epoch 的已证实事实，明确本地 epoch 不能承担因果证明。
- 1.3：新增 `SRC-AUD-006`，只把审计作为缺口和证据定位，不提升为上层需求。
- 3.2：保留 30 秒 deadline 和 response CAS；把 `control_epoch` 收缩为本地 record 排序、响应封口和禁止 restart/generation 复活。新增 dispatcher-owned `observed_process_state`，上游观察只按 session/generation/完整 owned identity 接受。
- 3.2：固定 paused 仲裁。public running 时真实 paused 必须转 paused；当前唯一 pause record 在 scheduled/issued 均以目标状态满足成功结算；已 settled 的 P1/P2 response、EVT-DYN-021、cache 和 queue 不改写；stopping/restarting/faulted 只更新 observed 状态，不结算不兼容 record。
- 3.2：固定 removal 仲裁。当前 terminate 首调或 retry 在 scheduled/issued 均可由 owned removal 成功结算；当前未 abandoned restart 仅在 deadline 前 removal 时继续；abandoned/settled restart 永不 Start 或增加 generation；terminal 清理、事件和旧 response 均只发生一次。
- 3.5：API-DYN-002 增加 active-owned 条件字段 `observed_process_state`；API-DYN-006 明确目标先退出的 error state；API-DYN-009 明确 retry 两阶段结算；EVT-DYN-021 pause policy 改为 `reconcile_owned_pause` 并否认上游 epoch。
- 3.6、IMP-004、IMP-005：同步固定上述观察兼容表、线程归属、响应封口、restart 禁复活和允许自行裁决边界。
- ACC-007、ACC-008、ACC-028、ACC-034：增加 P1 TIMEOUT→P2 scheduled/issued/settled→P1 late paused，pause-timeout 后 continue，T1 TIMEOUT→T2 scheduled/issued→无 token removal；逐例固定 observed/public state、旧/当前 response、EVT-DYN-010/021/terminal、cache/queue、callback 与恢复操作。

### 2.3 最小闭合条件与复审请求

最小闭合条件已满足。方案不再发明上游 epoch；P1/P2、T1/T2 的所有审计指定 barrier 均有唯一响应、状态、事件和资源结算；旧请求封口与真实目标状态对账被明确分离。

## 3. AUD-026 处理

### 3.1 判断

- 处理结论：同意。
- 风险：高。
- 问题层级：当前方案 artifact 信任/admission 实施契约缺口，不是可由 fallback 掩盖的异常清理问题。
- 方向选择：采用审计建议的第一方向，保留 128 个同进程 artifact session。第二方向“每个干净 root 只允许一次 artifact-bearing session”会实质收缩 REQ-DYN-010/RACC-DYN-007 的正常重复 dump 能力，并使既有 `artifact_sessions=128` 无真实语义；规范性来源没有支持该收缩。

### 3.2 实际修改位置

- CON-DYN-008：保留零自动删除。每次 CreateNew/commit 从同一 handle 建立 active-writer commit ledger；terminal lease 释放前，只有目录身份和完整 child 集合/path/file ID/length/SHA-256 逐项等于 commit ledger 才定格为当前进程 `known_retained`，禁止按 terminal 时碰巧存在的文件扩充允许清单。
- CON-DYN-008：每次写 admission 全量重验 known_retained 并持有无 write/delete sharing 的验证 handles 到 CreateDirectory/CreateNew/commit 决定结束。精确匹配只读计数且不阻断；新增、缺失、替换、改写、reparse、nested 或不可验证均 fail closed。
- CON-DYN-008：账本不持久化、不可从 marker 恢复。进程启动时账本为空，所有旧目录都是 `stale_untrusted` 并阻断新增；退出仍只能停扩展、由操作者清空 root、再重启，扩展继续零 DELETE/移动/覆盖/截断。
- API-DYN-001：新增固定 `artifact_policy={retention_scope=current_extension_process,restart_existing=stale_untrusted_fail_closed,automatic_cleanup=false}`；`artifact_sessions=128` 只表示当前进程 active_writer+known_retained 容量。
- IMP-009：把 active-writer commit ledger、terminal 定格、每次写重验、handle 持有、跨重启降级和不可自行裁决边界写成直接编码契约。
- ACC-002、ACC-019、ACC-022、ACC-028：验证 capability schema；增加 S1 dump→terminal→S2 dump 正例、terminal 后新增/缺失/原位改写/身份替换四类反例、未变 S1 的重启反例、128/129 边界、全量 hash 计数和全路径零 DELETE 证据。

### 3.3 最小闭合条件与复审请求

最小闭合条件已满足。同进程 terminal session、跨重启 session、terminal 后外部篡改现在是互斥状态；S1→S2 正常路径可达，篡改与重启路径 fail closed，任何分支都不恢复自动删除或以 marker 证明来源。

复审请求：全面复审。原因是 ArtifactRoot 的信任状态、账本来源、写 admission、能力公开语义及资源/性能边界发生变化。
